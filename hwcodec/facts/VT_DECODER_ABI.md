# VideoToolbox decoder plug-in ABI (iOS 16.7, 20H392 cache), plus the encoder selection facts that matter for P04

Read on 2026-11-11 by opus-dec3 from the decompressed dyld cache. Nothing here ran on the phone. The header is
`gpu/hwcodec/include/n2vt_dec_abi.h`. The evidence is regenerated by `gpu/hwcodec/facts/vt_decoder_abi.py`, which prints
symbols, addresses, slot tables and short instruction windows only. **[V]** means read in the cache at the address given.
**[I]** means inferred. Addresses are unslid cache addresses. No Apple code is copied: the header holds only layouts,
signatures and public enum values.

## 1. Loading and registration

| Fact | Evidence |
|---|---|
| `VTLoadVideoDecoders` calls `VTLoadVideoDecoder(path, entry)` once per bundle from a fixed list. The 5th call is `("/System/Library/VideoDecoders/Slim.videodecoder", "SLIMRegister")`, after H264SW (`VCPAVCRegisterDecoder`), VCH263, H264H2 and MP4VH2, and before AVD, VCPHEVC and the others | [V] 0x194cc7efc..0x194cc7f0c |
| `VTLoadVideoDecoder` does `dlopen(path, 4 /*RTLD_LOCAL*/)`, then `dlsym(h, entry)`, then a tail call `br x0` with no arguments. So the entry is `void SLIMRegister(void)`. A missing file or symbol is skipped silently | [V] 0x194cc807c..0x194cc80b8 |
| `VTLoadVideoDecoders` runs once, inside `vtCreateAndPopulateVideoDecoderRegistry`, after the built-in decoders have been registered (DolbyVision, JPEG, MuxedAlpha, ...) | [V] 0x194ed0e58 |
| `VTRegisterVideoDecoder(type, create)` is the same as `VTRegisterVideoDecoderWithInfo(type, NULL, create)` | [V] 0x194cc80bc |
| `WithInfo(w0 codecType, x1 info, x2 create)`: the codec type becomes a 4-char ASCII CFString. If `info["CMClassImplementationID"]` exists, the ID becomes **`<ID>.<4cc>`** (the 4cc is appended). Otherwise it is `com.apple.videotoolbox.videodecoder.anon-%d` | [V] 0x194cc8138..0x194cc8210 |
| On a mutable copy of `info`: **`VTIsHardwareAccelerated` defaults to `kCFBooleanTrue` when absent**. `VTCodecType` is set to the 4cc. `VTRating` gets an int32 0 only if absent (CFDictionaryAddValue). `VTAllowSandboxedDecode` is always set to `kCFBooleanFalse`. | AppleAVD registers through plain `VTRegisterVideoDecoder`, so it gets hardware=true and rating 0. On the Nord 2 its CreateInstance presumably fails because there is no AppleAVD IOKit service | [V] 11 calls in AVD.videodecoder. [I] that it fails |

## 2. Object layout

The base class record is the same 11-slot record (0x58 bytes) as the encoder's `n2_CMBaseClass` in `n2vt_abi.h`. The vtable is
`{NULL, &base, &decoderClass}`. The object is created with `CMDerivedObjectCreate(alloc, &vtable, VTVideoDecoderGetClassID(), &obj)`
(callers: every built-in `*_CreateInstance`, e.g. 0x194f0693c).

Decoder class record: 11 slots, 0x58 bytes [V] (`_kParavirtualizedVideoDecoder_VideoDecoderClass` @0x1d69e8db8. The next vtable starts 0x58 later).

| Off | Slot | Version | Named by the symbol and by the VideoToolbox caller [V] | Signature |
|---|---|---|---|---|
| +0x00 | version | | Paravirtualized=3, MuxedAlpha/JPEG/DepthWrapper/DolbyVision=2, VCH263/MPEG4/WebKit VP8/H1JPEG=1 | uint64 |
| +0x08 | StartSession | 1 | `VTDecompressionSessionCreateWithOptions` 0x194cf8ebc | `(dec, session, CMVideoFormatDescriptionRef)` [V mangled name] |
| +0x10 | DecodeFrame | 1 | `vtDecompressionDuctDecodeSingleFrame` 0x194ccbba4 | `(dec, frame, CMSampleBufferRef, uint32 flags, uint32 *infoOut)` [V mangled name and registers] |
| +0x18 | CopySupportedPropertyDictionary | 1 | `VTDecompressionSessionCopySupportedPropertyDictionary` 0x194ccb334 | `(dec, CFDictionaryRef*)`. -12782 or 0 accepted |
| +0x20 | SetProperties | 2 | `VTDecompressionSessionSetProperties` 0x194cfab7c | `(dec, CFDictionaryRef)`. -12782 makes VT set the keys one by one |
| +0x28 | CopySerializableProperties | 2 | `VTDecompressionSessionCopySerializableProperties` 0x194cfacd8 | `(dec, CFAllocatorRef, CFDictionaryRef*)`. -12782 is mapped to 0 |
| +0x30 | CanAcceptFormatDescription | 2 (guarded) | `VTVideoDecoderCanAcceptFormatDescription` 0x194cfbfc4, `vtDecompressionSessionDecodeFrameCommon` 0x194cfbccc | `Boolean (dec, CMFormatDescriptionRef)`. NULL means false |
| +0x38 | FinishDelayedFrames | 2 (guarded) | `VTDecompressionSessionFinishDelayedFrames` 0x194cfc1a0 | `(dec)`. -12782 is mapped to 0 |
| +0x40 | StartTileSession | 3 | `VTTileDecompressionSessionCreate` | not used |
| +0x48 | DecodeTile | 3 | `VTTileDecompressionSessionDecodeTile` | not used |
| +0x50 | FinishDelayedTiles | 3 | `VTTileDecompressionSessionInvalidate` | not used |

"Guarded" means VT checks `version >= 2` before it reads the slot (`cmp x9,#2; b.lo`). SetProperties and CopySerializableProperties
are called whenever they are non-NULL. Base-class slots used by VT: `+0x18 invalidate` (session invalidate and duct finalize),
`+0x30 copyProperty` (`VTDecompressionSessionCopyProperty`. VT asks for `UsingHardwareAcceleratedVideoDecoder` right after
StartSession: answer `kCFBooleanTrue`), and `+0x38 setProperty` (twice before StartSession, then per key. The return value of
the first two calls is ignored).

The factory is `OSStatus (*)(uint32 codecType, CFAllocatorRef, VTVideoDecoderRef *out)` [V, mangled
`createWebKitVP8Decoder(unsigned int, __CFAllocator const*, OpaqueVTVideoDecoder**)` @0x1d5168274]. A factory registered
with `VTFactoryFunctionHasSpecificationArgument=true` gets 5 arguments (Paravirtualized). We do not use that form.

## 4. Selection and fallback (the facts that shape DEC06 and P04)

1. **Sort.** `vtSortRegistryItemsByRating` @0x194ed1c58 puts the higher `VTRating` first. On a tie, `VTIsHardwareAccelerated=true`
   comes first. [V]
2. **Filter** (`vtFilterRegistryItemByCodecTypeAndVideoDecoderSpecification` @0x194ed12e0): it matches `VTCodecType` (a string or an
   array of strings), `DecoderID`, the process allowed-list (`VTRestrictVideoDecoders`/`VTGetAllowedDecoderList`) and
   `VTAvoidHardwareDecoders`, and it skips paravirtualized decoders unless they are allowed. [V] The `RequireHardwareAccelerated...` /
   `EnableHardwareAccelerated...=false` handling is in `VTSelectAndCreateVideoDecoderInstanceInternal` @0x194cc7408 (it reads both
   keys at the top). Its exact effect on software candidates is [I].
3. **CreateInstance failure means the next candidate is tried.** A non-zero status, or a zero status with a NULL instance (VT
   then signals -12911), continues the candidate loop. The last error is returned only if every candidate fails.
   [V] 0x194cc7be0..0x194cc7ccc.
4. **A StartSession failure is NOT retried for decoders.** `VTDecompressionSessionCreateWithOptions` calls StartSession once.
   On error it finalizes the duct and fails the session create. [V] 0x194cf8eb0..0x194cf8ef8.
   **Consequence:** the "is vcodecd usable" decision must be made in **CreateInstance**. An unsupported *stream*
   (profile, size, 4:2:2) is discovered only in StartSession, and a failure there kills playback. For those streams the
   decoder must either accept them through an internal software path (a nested `VTDecompressionSession` pinned to Apple's
   `DecoderID`, as MuxedAlphaDecoder does with `alphadecoder_createSubLayerVTDecompressionSession` @0x194f076d4), or be
   gated tightly enough that it never sees them.
5. **Out-of-process decode.** In a non-server process (Camera, Photos, any app), `VTDecompressionSessionCreateWithOptions` goes
   through `VTDecompressionSessionRemote_Create` (FigRPC to the service `com.apple.coremedia.decompressionsession`) unless
   `VTRunVideoDecodersInProcess` is set or the option `AllowClientProcessDecode` is passed. [V] 0x194cf8710..0x194cf88d0 and
   0x194f42030. So **Slim.videodecoder is loaded and runs inside the media server** (mediaserverd [I]). Its access to
   `/dev/redwood-vcodec-client` (the relay used by the P03 client) must be allowed by that process's sandbox [I, risk]. The
   same question applies to encoders: check where the proven `N2VIDEO ... registered` line was logged.
6. **Mid-stream format change.** `vtDecompressionSessionDecodeFrameCommon` calls CanAcceptFormatDescription (version 2 or later) when a
   sample carries a new format description. A true answer waits for the async frames and keeps the decoder. A false answer
   makes the session replace the decoder [I].
7. **DecodeFrame status -17690** is passed through without a FigSignalErrorAt. It is presumably kVTVideoDecoderRemovedErr and
   may lead VT to rebuild the decoder [I]. It is not usable as a fallback until that is verified.

## 5. Encoder side (resolves P04 F32)

| Fact | Evidence |
|---|---|
| Encoder candidate loop: a CreateInstance error or a NULL instance tries the next candidate, as for decoders | [V] `VTSelectAndCreateVideoEncoderInstanceInternal` 0x194ed8200..0x194ed82ec |
| **An encoder StartSession failure IS retried.** `VTCompressionSessionCreateWithOptions` remembers the first error, invalidates and releases the instance, and calls the select function again starting at `chosenIndex + 1`. It ends only when no candidate is left, and then returns the first error. **Any** non-zero status counts, so -12915 works as P04 intended | [V] 0x194cd5b20..0x194cd5c70 (start index x4 = x20, chosen index stored at session+0x1b8) |
| Encoder sort (`vtSortRegistryItemsByVideoEncoderRating` @0x194ed936c, result negated at 0x194ed9590): higher `kVTVideoEncoder_Rating` first, then hardware first, then `CMClassImplementationID` in **descending** CFStringCompare order (`com.nord2.*` before `com.apple.*`) | [V] |

So P04's StartSession -12915 fallback is correct as far as VT is concerned. The remaining risk is time: the default
client timeout is 5000 ms for connect and for every frame (`N2VCD_CLIENT_TIMEOUT_MS`), all of it inside StartSession or
EncodeFrame.
