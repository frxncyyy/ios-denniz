# Private fresh WFSYS-to-ROM_DONE candidate

Source pin: selected Android `../nord2-current-kernel` commit `04d00c2565764c3922c9b4826b5acff1106e533f`, `drivers/misc/mediatek/connectivity/wlan/core/gen4m/chips/soc3_0/soc3_0.c:1565-1643,2295-2375`, `drivers/misc/mediatek/connectivity/conninfra/platform/mt6893/mt6893_pos.c:2367-2376`. This is private, default-off source. It is not wired to active XNU, boot images, CI or a device.

`nrpa_start` requires an already prepared `struct nrb_native` from `nrb_xnu_prepare` in a sleepable UFS-ready context and a fresh, zeroed `nrpa` object. The owner hook must prove the persistent phase-10 common owner without touching old asleep `nwsa` or one-shot `nawa`. The only opt-in value is `1`; disabled and reentry calls execute no callback. The adapter performs AP-only host guards before AP wake, then its stage-specific radio register allowlist. Six always-on AP predicates are checked before every guarded access. The real native policy and placement functions are called on the **same prepared object**; their owner callback checks this new state, never a caller-supplied memory-permission boolean.

After separate AP and WF votes, CFG readability, and five cold WFSYS/BGF reset and power observations, `nrb_xnu_policy` issues the real region-27 group 1/group 0 SET under the current claim. It runs before CPU reset assertion, semaphore-20 PLL votes and WFSYS power. Any policy uncertainty stops with the fresh votes owned for manual reset. The tested WFSYS path then asserts CPU reset, acquires BPLL/WPLL with semaphore 20, powers WFSYS, removes protection, sets VDNR and reads local ID `0x20010000`. `nrb_xnu_place` snapshots and verifies four firmware spans while the new CPU remains held. The core checks the actual native state: two accepted raw-zero SET results, phase 7, complete backup, mapped placement, two barriers and write/read counts derived from all four 4096-byte chunked spans. Its adapter checks that receipt again at the CPU-reset write.

Only then it writes AP2WF `0x18001120=0x89040000`, clears the two dynamic entries `0x185001dc/1e0`, clears semaphore reset bit 0, and deasserts CPU reset. `cpu_release_attempted` latches immediately before the final write; a failed or uncertain callback retains all votes and WFSYS power, with `cpu_released` remaining false. It polls `0x184c1604` for `0x1d1e`, at most **102 reads**: one initial read plus 101 delayed reads at 1000 µs, matching the selected source's `polling_count > 100` test. After ROM_DONE, it performs the selected `conninfra_config_setup_mt6893` literal write `0x1800f000=0x32c8001c`, releases WPLL then BPLL under semaphore 20, clears the fresh WF vote and finally writes AP sleep. It performs no MMIO or proof callback after that final sleep. Success deliberately leaves WFSYS powered, protection removed and CPU running, with AP/WF/PLL/semaphore votes released.

All failures after side effects halt with retained ownership; there is no speculative reset, power-off, firmware restore, alternate SET, SMC getter or permission inference. ROM_DONE is a firmware-start marker, not an iOS Wi-Fi interface. No production/device execution is claimed.

`rom_bind.inc` is the proposed private native binding. `nrpa_prepare_before_power` runs after `ni_wifi_snapshot` in the sleepable input thread and before `ni_wifi_power_probe`; the existing native prepare function gates exact `nord2wifirom=1`, current ADT claim, high-RAM layout and authenticated vendor-file supply. A preparation error is logged and skips the ROM radio attempt before any new radio mutation. The retained phase-10 branch calls `nrpa_after_persistent`; it rejects old `nawa`/`nwsa` objects, checks the existing common owner, maps BRCM/local/dynamic/ROM_DONE pages, and starts a fresh `nrpa`. AP2WF shares the retained CFG mapping and debug control shares the retained debug mapping. Raw native callbacks split read/write addresses; CPU reset bit 0 is allowed only at stage 12 with the same native placement receipt and an attempted-release latch. A captured-only log precedes that write. A second captured-only log in private `rom_xnu.c` precedes each real SMC group. No diagnostic MMIO is added. The proposed `sweet_touch.rom.candidate.c` and `integration.patch` show exact hook placement; they are not promoted. The planned boot image must omit old `nord2wifiwake` and `nord2wifiwfsys` flags.
