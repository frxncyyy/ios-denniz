# WFSYS to ROM-ready: next private milestone (source only, 2026-10-21)

Selected Android source: `../nord2-current-kernel` HEAD `04d00c2565764c3922c9b4826b5acff1106e533f`. Current iOS phone evidence is persistent common phase 10, ADIE `66358a11`, retained handoff 2 (`NOTES.md`); AP wake image `6978794fde46fd1410c631eb0ee4b918a6065c2a` is built/packing but has **no hardware result or new boot approval** as of this note. This is a private implementation plan, not a live test, permission proof, or authorization for MPU SET, DRAM writes, or WFSYS CPU release.

## Smallest useful successor to AP wake

Build one default-off **CPU-held WFSYS bring-up through its local version**, with a source-first ROM-ready boundary. Do not split WF vote, clock bit, power bit, and local-ID reads into arbitrary images: each later read depends on the ordered state established before it. Start only after AP wake has independently shown its own reference/ack/readability/identity and balanced sleep on the phone. On entry, hold the persistent common owner, reacquire the AP/ON-domain wake reference, then acquire the *distinct WLAN* HOST `0x180601a4[0]` vote; do not substitute the conninfra `0x180601a0` vote. After its ack/readability/CFG identity, assert `0x18000010[0]=0` and retain a cold/no-CPU-release invariant. Source: `soc3_0.c:1565-1640,2150-2180`; AP-wake contract: `next-after-persistent.md:5-11`.

Acquire WIFI's BPLL+WPLL ownership through the selected `conninfra_bus_clock_ctrl(WIFI,ALL,1)` semantics: per-radio vote, semaphore 20, AFE `0x18003008[21]`, 30 us, `[20]`, 50 us. Replace its unbounded semaphore retry with a finite budget and preserve acquired-vote state on uncertainty (`mt6893.c:447-530`). Key WFSYS top power at `0x18000000` with preserved low fields and `0x57460080`; poll HOST `0x180602cc[2]=1`; recheck conninfra readability; release WF and WFDMA protections `0x18001620/1624[0]` and poll each `[3]=0`; enable VDNR `0x1800e06c[0]`; **only then** read local `0x184b0010==0x20010000` (`soc3_0.c:2180-2313`, `soc3_0.h:105-124`). Keep all polls bounded, log only exact stage/status/owner state, and halt on ambiguous MMIO or ownership. A software deadline cannot interrupt a stalled MMIO access.

For the first hardware acceptance, stop at that local version with CPU reset asserted and no EMI mapping/copy. A reviewed, bounded reverse path can protect both WF links, power WFSYS off, release only owned clock/WF/AP wake votes after acknowledgments; source power-off order is in `soc3_0.c:2380-2540`. If any transition is uncertain, retain state and require manual reset instead of claiming restoration. Success proves this WFSYS path and local-ID aperture, **not** ROM placement, MPU access, firmware execution, or Wi-Fi service. This is a meaningful combined WFSYS stage while the independent DRAM gates below are resolved. Prepare it offline with fault-injection and native binding review before any later image/approval discussion.

## Exact subsequent ROM transaction, still CPU held

The selected full-init order places ROM **after** local version and **before** AP2WF remap, dynamic entries, semaphore reset, and CPU release (`soc3_0.c:2295-2359`). `gen4m/Makefile:145` enables power-on EMI ROM download for SOC3_0. `soc3_0_wlanPowerOnDownload` maps MCU ROM first, then Wi-Fi ROM (`soc3_0.c:3110-3180`); the header parser copies payload after the 48-byte header and then each 16-byte datecode (`soc3_0.c:3031-3060`, `soc3_0.h:138-139,218-226`). `wlanDownloadEMISection` masks the firmware address to a 24-bit offset and copies through a mapped CONN EMI base (`chips/common/fw_dl.c:452-484`, `include/chips/fw_dl.h:107-109`). The selected MT6893 `kalSetEmiMpuProtection` hook is empty (`os/linux/plat/mt6893/plat_priv.c:284-287`); that wrapper grants no missing permission.

For the *historical* Android `CONN 0x8fb00000+0x450000`, the authenticated local planner `shim/nord2-xnu/wifi_rom_plan.{c,h}` and `research/nord2/wifi/firmware/download-layout.json` identify these four destination spans, all within the CONN range. Offline file SHA256/header/length/bounds checks already exist in `wifi_rom_plan`; the independent `wifi_rom_transaction` is a memory-only snapshot/copy/readback/restore helper with **no native I/O or activation hook** (`shim/nord2-xnu/wifi_rom_transaction.{c,h}`). Its prerequisite callbacks are assertions for a future audited adapter, not evidence. Build a guarded native mapping/visibility/restore owner only after the gates below are satisfied. A first copy acceptance should restore all four original spans and verify restoration while the CPU stays held; any partial write or unverified restore is dirty, preserves backup and forbids handoff. A later persistent placement/CPU-release image requires its own reviewed lifetime and approval.

After successful persistent placement, selected source writes AP2WF `0x18001120=0x89040000`, zeroes `0x185001dc/1e0`, clears `0x18000018[0]`, then deasserts **CPU** `0x18000010[0]=1` and polls `0x184c1604==0x1d1e` (`soc3_0.c:2317-2359`, `soc3_0.h:125-139`). It drops clock and WF force-on votes only after ROM completion. CPU release is firmware execution and remains a separate milestone; neither local ID nor restored-copy success implies it is ready.

## Reservation and protection gates before any destination access

The saved live DTB and `dtb/nord2/live.dts:1099-1106` express `consys-reserve-memory` as `no-map`, size `0x450000`, alignment `0x100000`, alloc-range `0x50000000+0x40000000`, with **no fixed `reg`**. A bounded `dtc` decode of valid embedded FDTs in saved `backup/nord2/lk.img` (2), `lk2.img` (2), `boot.img` (23), and a saved local `shim/out/nord2-xnu/nord2-xnu-boot.img` (23) found the same two CONN nodes per image, no CONN `reg`, and no `emi-addr`/`emi-size` property; `live.dtb` has the same dynamic form. This is static-image evidence, not a decoded current LK runtime tag or current allocation. The historical Android log `backup/nord2/post-probe-dmesg.txt:1874` says CONN `0x8fb00000`, MCIF `0x8a000000`; saved `iomem.txt:416-418` has the matching Android RAM gap (see `monitor-abi/permission-interpretation.md:37-40`). Neither proves this iOS boot reserved that exact range. `memory-ownership/REPORT.md` proves only that the current XNU advertised high RAM and reviewed fixed aliases avoid it. MCIF is CCCI-owned (`mt6893_emi.c:106-137`) and is excluded from ROM storage.

Before allowing the ROM adapter to map/write, establish a **current boot** fixed CONN carveout contract: chosen base/size tied to loader/ADT or another preserved boot allocation record, outside XNU allocation, modem/CCCI and other consumers; exclusive span ownership and no cached alias; an explicit uncached/device mapping, ordering and visibility rule for AP writes and the later CONN fetch. Do not set `NWRT_RESERVATION`, `NO_ALIAS`, `EXCLUSIVE`, `MAPPING_POLICY`, or `PERMISSION` merely because historical Android picked `8fb00000`. Review source loader/ADT reservation at `tools/mkadt-nord2.py:29-30,65-66` and `shim/nord2-xnu/loader.c:513-617` against this chosen contract. If boot tags do not carry a chosen address, a deliberate iOS-owned fixed reservation design is an implementation task; the saved images supply no current chosen-base authority.

The selected Linux source has an **owned setter policy** independent of any getter: `consys_hw.c:760` calls `emi_mng_init` before PMIC; `emi_mng.c:209-240` resolves CONN base/size then invokes MT6893 region 27; `mt6893_emi.c:88-103` requests AP0, CONN2 and SCP3 unrestricted, other domains forbidden. The selected `emimpu_old.c:819-860` issues `SMC64 c200050b/action0`, group 1 then group 0, but ignores both SMC results. Backed-up ATF disassembly shows group 0 forces bit 31/software lock and may reject an already locked region or validator state before all writes (`monitor-abi/region27-source-policy.md`; current monitor identity remains unproven). The failed legacy getter does **not** inherently block an explicitly owned setter design. It also cannot establish inherited permission or rollback. Implementing this policy requires exact chosen range/domain values, current monitor route and raw return/error handling, partial-write/one-way-lock fail-stop semantics, and an explicit persistent ownership decision. No speculative SET, alternate FID, clear/unlock, region substitution, or ignored status is a valid gate. Even a successful setter return would not prove overlap priority/effective access without the mapping and ownership contract.

**Current blockers:** AP-wake hardware acceptance; current iOS CONN chosen-base/reservation and cache-alias ownership; reviewed source-owned region 27 acceptance/persistence contract and effective AP/CONN visibility; native WFSYS owner/failure integration. **Implementation already supported offline:** exact WFSYS state machine through local ID, authenticated four-span ROM plan and bounded restore helper. Keep these independent of UFS/boot work and of any future RF/NVRAM/networking claim.
