## What exists and what is gated

`npa_start` is one-shot/default-off and pins historical Android/source CONN8fb00000 and MCIF8a000000 (MCIF0 remains the vendor optional-absent alternative). Parent explicitly approved these historical addresses as **register-only private design provenance**, not current exclusive DRAM ownership. MCIF belongs to CCCI; no RAM mapping/read/write, MCIF clear, MPU SET, CPU release, DMA or firmware placement occurs. The only new RAM aperture is cold reset **subsystem SYSRAM18050000+4000**, as selected vendor source requires. Parent memory-ownership report establishes these DRAM ranges are outside XNU allocator/fixed aliases but not exclusive hardware ownership. Those limits remain relevant before any later firmware consumer.

Concrete source remap precedes D-die: HOST01c4=(CONN>>16), WF/BT/GPS01d4/1d8/1dc=1000 and optional MCIF01cc=(MCIF>>16), all maskfffff preserving upper bits. Each mask readback is verified before advancing. Source uses these fields and reads the CONN/MCIF values for logging; candidate adds checked masked readback. First remap write already retains the outer lifetime; failure cannot fall into old cleanup.

Current exact source copy still requires **nord2wifi=2 plus nord2wifipersist=1**. Persistent mode branches before legacy ncc_power_window, so it never calls restoring common/ID scope. Default mode retains the original branch. Persistent refusal does not fall back to the legacy diagnostic. `npa_persistent_lifetime` is set before the first raw hardware write and never cleared; successful phase10 skips original outer restore explicitly. `nw_restore` immediately refuses with no MMIO whenever lifetime is retained. `nord2_input_prepare_return` rejects before PMIF/GPIO cleanup, and another power probe panics before clearing fresh owner state. Dirty/uncertain failures panic with power/ownership retained. Current input thread continues its normal touch/key initialization/polling after successful source initialization; its pins20/21/155/202–205 do not overlap WiFi GPIO180. No new thread or PMIF owner was created.

## Access/phase restrictions

Raw backend maps exact powered apertures: RGU,CFG,thermal,AFE,SPI,WTtable,FM,debug,HOST,semaphore,16KiB subsystem SRAM; existing GPIO and SPM maps are reused. There is **no** mapping for8fb00000/8a000000. Adapter callbacks allow only the common40 table, enumerated selected control fields and exact16KiB source clear/handoff region; masked writes require a matching preceding read and preserve other bits. GPIO SET aliases are exactly bit20. Full-register source writes remain full-register writes; source core is trusted after review, not interpreted as arbitrary external commands.

Every generic check retains fresh AP power/readability, all13 WFSYS/BGFSYS/radio/master idle predicates, positive AP RCbit and software owner proof. It deliberately excludes SPIbusy from generic cold predicates because we can own an in-flight command; SPI transport handles busy separately. It does not require our A-die reset or source calibration registers to remain at their pre-init values. Source-clock26MHz selection and initial RC/1.3V/common PMIC checks come from selected source and unchanged outer setup; parent must still review persistent rail requirements against temporary probe before hardware acceptance. The source-owner proof function checks original cold baselines, saved PMIC masks and existing exclusive input-thread lifetime rather than granting proof from an arbitrary true callback.

Before taking semaphore11 or19, bounded clock/IRQ checks reuse existing tested diagnostic policy: reset host clock detector once, poll readybits6 up to1600 (initial1us then10us), require IRQbit0. This is the existing accepted diagnostic variation from vendor resetting detector on each retry, not claimed byte-exact clock polling. Semaphore1000*1us acquisition reads are side-effecting; no snapshots/reacquisition for release verification. Sem11/19 cannot nest. Read error/unknown completion preserves core ownership uncertainty and invokes fatal manual-reset path.

TOPSPI TOP only: read formatb000 or writea000; explicit source-address allowlists; status18004000busybit5 initial read plus source macro count>100, reread/delay50 => at most101*50us delays per busy stage. Address050 written before WD054 trigger; `spi_inflight` is set **before** trigger. Unknown callback completion or posttrigger busy timeout retains semaphore/inflight and halts without replay/release. A completed read consumes RD058. No alternate subsystem command, firmware download or efuse burn opcode is emitted. Source mode00/address0 efuse kick is the core's documented read operation; analog limitations remain as phase10 report explains.

Final source HW handoff uses a terminal adapter state: before clearing1a00bit23, retain/latch the terminal path; thereafter callbacks permit only exact source1860 read then ORbit0 write. No AP owner checker, clock probe, cold predicate or unrelated CONN access follows. Successful final write marks terminal2, then returns software result/log only. Tests instrument backend to assert this. Any later radio operation requires a separately source-backed wake transaction; phase10 is not persistent MMIO readability or network readiness.
