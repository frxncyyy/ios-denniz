# Retained configuration core (supersedes reversible-only DESIGN conclusion)

Parent clarified persistent initialization is intended: ordinary source-backed analog configuration does not need universal rollback. `retain.c/h` implement an injected private core that keeps owned CONN state configured and stops on failure. No automatic analog restore, trigger replay, CPU release, firmware load, SMC, WFSYS power/reset write or networking. It is NOT linked, a native adapter, a boot image or a completed common initializer.

Selected source04d00c25, E3/26MHz/WiFi-only path:

1. Fresh mandatory check: exclusive owner, positive CPUreset/WFSYS/BGFSYS cold, all radios/DMA idle, source CONN power/identity/readability,26MHz and bounded transport, owned SRAM18050000+4000, EMI remap already completed. Check callback remains fresh between operations but must allow our A-die reset/common changes. The native implementation of this proof is an integration gap, not manufactured by the core.
2. Exact D-die efuse-to-SYSRAM handoff/buildword (optional buildmode1..3), then reuse existing common40 table (four retention words +36 non-BT SPI settings). These are **retained**, not ncc_run's rollback transaction. Source buildmode selection must be pinned before native integration;0 reproduces an absent compile-time build mode.
3. Vendor A-die16KiB SYSRAM clear **after** D-die/SPI and **before** GPIO180 strap/reset/ID. This clears the earlier D-die/buildword, exactly as selected source does. Ownership is of cold-reset subsystem SRAM, not arbitrary DRAM. All4096 words written via ordered32-bit callback; do not allocate a16KiB snapshot on input stack.
4. GPIO18026MHz strap, A-die reset deassert, TOPSPI E3 ID gate, ID handoff, source064/0bc writes, FM extension clear and thermal address. Existing TOPSPI ID allowlist cannot be used unchanged: a new private transport adapter must implement exact TOP readb000/writea000 and completion semantics under sema11.
5. Efuse source read-mode00/address0/kick30 with70*30us bounded polling, validity29, four private efuse handoffs, conditional thermal034/038 masks in source order. Source has no burn/high-voltage enable command here; its explicitmode00 read path is implemented. Initialbusy rejects, never clears another operation. Failed/ambiguous transport immediately returns dirty/halt and retains semaphore/power. Invalid completed efuse follows source by continuing without handoffs/thermal register changes. No raw efuse log or exported result.
6. Remaining E3 A-die pad/LDO/XOBUF/IR values, GPIO return to CONN mode, source AFE register/enables/delays and final070=5, then PLL values. Returns phase7 **PLL-retained only**.

Changes from vendor's permissive error handling are deliberate fail-stop guards: any failed read/write/delay/check/semaphore callback stops immediately, no later callback/cleanup; every mutation marked before issuing; unknown efuse busy forces manual reset; actual ID must be66358a11. Successful SPI commands release our semaphore in vendor grouping; failures do not release it speculatively. Callback failure on acquisition conservatively leaves semaphore-held uncertainty, requiring halt. A caller must not use existing outer/common auto-teardown after retained or dirty state. One owner must keep prerequisites live and prevent reentry for the rest of boot.

## Remaining concrete implementation gaps

- Native bounded transport + clock/IRQ/semaphore adapter, address/value allowlists, positive cold CPU ownership and retained-lifetime integration are **not implemented** here. CPUreset/power snapshots from earlier diagnostics must be freshly repeated; exact SRAM access must be tied to selected DT index and mapping. No full hardware register manual is required just to implement vendor values, but all native address/command handling still requires review.
- Before this core: common PMIC/clockbuffer/pinmux/power/AXI sequence and EMI remap. Current outer diagnostic restores power; persistent owner must replace that lifetime intentionally. This core accepts completed remap as a mandatory external prerequisite and does not quietly omit it from full-init claims.
- After PLL, consys_hw.c:382–389 still calls subsystem status/voltage/low-power/PMIC low-power. Low-power includes E2/E3 analog tables, A-die top-clock control/semaphore and digital controls; it is not implemented by this phase7 result. No WFSYS initialization may call phase7 'full common ready'.
- Source software thermal metadata update is not published by this private diagnostic core. Before a persistent driver consumes temperature it needs per-owner metadata from privately retained efuse1; current efuse locals intentionally do not escape. No Android global callback was silently substituted.
- Source AFE has analog calibration transitions although no RF packet/firmware starts; hardware use needs the parent's review/image approval. Retained source configuration correctness is not runtime-verified by mock tests.

## Verification

`test.c` mocks transport; success verifies retained phase7/E3, cold SRAM clear and no CPU/power release addresses. Fault injection at all8586 callback positions requires immediate stop with no further callback and dirty/semaphore uncertainty latched. Separate efusebusy70timeout, invalid-efuse continuation and default-off cases pass. Host C11 Wall/Wextra/Werror and ASan/UBSan both pass (`test.log`). This is meaningful lifecycle/order testing, not actual analog/MMIO acceptance. No native compile/CI/device action.

The earlier DESIGN inventory and source links remain useful, but its conclusion that analog rollback semantics universally block source-backed initialization is superseded by this retained-state implementation. Full native completion remains the explicit gaps above rather than a universal hardware-documentation requirement.
