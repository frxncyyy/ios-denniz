# Private native ROM placement candidate

No active hook, hardware call, CI, physical RAM access or production edit was performed. `rom_xnu.c` contains the future native implementation, default off unless exact `nord2wifirom=1`. Host tests replace physical mapping/SMC/UFS with heap memory, raw-result mocks and bounded saved vendor-file reads.

## Invocation and lifetime

1. Zero one `struct nrb_native`. Call `nrb_xnu_prepare` from sleepable UFS-ready context **before** entering the fresh powered radio critical lifetime. It authenticates the existing four-file supply via `nwf_load`; planner rehashes the two ROM files. It consumes only the current `/chosen/nord2-conn-claim` 24-byte LE record (base u64,size u64,source u32,valid u32): source3/valid1 and exact8fb00000+450000. No historical fallback. The parent's loader claim is the explicit reservation policy; it does not prove every other master is quiescent.
2. Bind the same object through `nrb_xnu_policy(n,fresh_owner,ctx)` after new AP ownership and cold WF/BGF reset/power proof, **before WFSYS power**. The callback must prove real ownership, never assert MPU permission. Source-pinned region27 SET is internal: group1 then group0, raw x0..3 recorded, only x0=0 accepted. First nonzero/transport error stops, including positive200c. Group0 can install a software lock before validation. No retries, rollback, getter assumption or Linux return-zero assumption. Two SMC invocations are bounded in count, not interruptible in time.
3. Parent powers WFSYS with CPU held using its fresh owner. Call `nrb_xnu_place` on the same object. Owner stage2 must prove retained AP/WF votes, semaphore ownership, readability/clock/local ID20010000, CPU reset held and sole current CONN consumer. Never use old balanced/asleep `nwsa_start` state. Map exactly the claimed CONN range once. Snapshot all four spans, then persist all payload/date spans in vendor order, barrier, full readback, barrier. Only those planned spans are accessed, in aligned <=4096-byte chunks. No MCIF, other DRAM, WFSYS CPU release, ROM_DONE or RF commands here.
4. Real receipt is that same object's state: phase7,placed1,accepted2,issued2,raw_valid3,both raw x0 zero,backup_complete1,write_attempted1,halt0,error0,88writes,176reads,2barriers. Parent may proceed toward CPU release only after checking it. Verified source, scratch, backup and permanent alias remain retained for the firmware lifetime. No implicit restore, unmap or free on success or post-policy failure. Any ambiguous policy/map/write/readback error requires manual reset with ownership retained. Sources must remain immutable and all backing storage disjoint.

## Mapping/cache and visibility evidence

Selected XNU `research/ci-39158169212/buildtree/xnu/osfmk/arm64/machine_routines.c:1556-1560`: `ml_io_map` requests VM_WIMG_IO. `osfmk/arm/io_map.c:88-134` maps the range permanently; no normal-WB mapping is requested. `osfmk/arm/pmap/pmap.c:5652-5665` chooses Device-GRE for `is_dram_addr`, Device-nGnRnE otherwise, NX/PNX. `osfmk/mach/arm/vm_param.h:302` defines that test against gDramBase/Size; `osfmk/arm/arm_init.c:662-680` initializes them from chosen dram-base/size. Parent `rom-loader-candidate/mkadt-nord2.py:65-66` uses high142000000+3e000000. Native layout checks bootargs **and** those current ADT properties before preparation and each ownership check; low8fb00000 is outside that window and gets Device-nGnRnE under this source.

`shim/nord2-xnu/loader.c:600-615` writes equal memSize and memSizeActual. The closed selected build's allocator/high-window and fixed-alias exclusions are documented in `../memory-ownership/REPORT.md`; this candidate creates only one Device alias, with aligned volatile32 accesses and dsb sy after IO and at transaction barriers. There is no WB alias to clean in this closed design. This is a source proof, not an observed PTE/hardware cache experiment; new aliases or other DRAM users invalidate the ownership premise. Full AP readback plus DSB establishes AP copy completion, not secure policy priority/overlap or actual CONN fetch; later ROM_DONE is the empirical consumer check. Do not claim it now.

AP0/CONN2/SCP3 permission0, other13 permission5. Runtime policy acceptance and lock behavior remain an approval boundary; unsupported getter is neither a prerequisite nor proof.

Existing `wifi_rom_plan.c` authenticates complete ROM bytes and pins 48-byte headers. Four destinations, source order: MCU payload8fd30000/49820, MCU date8fd7f0e0/16, WiFi payload8fdb0000/296868, WiFi date8fd7f0f0/16. Total346720.
