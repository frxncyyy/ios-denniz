Saved dtb/nord2/live.dts contains no connfem-compatible node. `connfem_module.c:52–88,385–439,470–487` initializes global context null and only registers a context from matching platform probe. The only nonnull assignment is probe439; no alternate file setter was found in this selected module. `connfem_api.c:65–140` explicitly memsets each getter output before returning -EOPNOTSUPP on null context. LAA chip_id is assigned6893 only with a real context. `wlanSendPhyAction:519–522` ignores getter return codes and copies the full outputs. The candidate accepts that path only with exact pinned WIFI+DT hashes and explicit selected_getter_no_context policy. A changed/currentboot DT or later ConnFem provider must invalidate/review this policy; do not turn all-zero fields into a generic success default. If a context is introduced, derive FEM id/pins from the selected connfem DT parser, including board HWID, parts and pinctrl selection; do not guess a nonzero id or reuse zero policy.

## Command and response contract

`include/nic_init_cmd_event.h:132–162,239–291`: init CID8, packet typea0, response EID5. PHY header is LE{magic556789aa:u32,tagcount4:u8,version1:u8,bodylen:u16}; tags LE{tag:u16,len:u16}. Order for FORCE_CAL and BACKUP is CAL1 length4(command byte+3 reserved), NVRAM0 length228, COM_FEM2 length104, LAA3 length40. Total TLV payload400, body392. This excludes normal MAC/init descriptor headers and any alignment imposed by the actual selected NIC_FILL_CMD_TX_HDR. Reuse reviewed transport filling, not an invented generic full command header.

`pre_cal.c:154–285` waits on image-download status port, then checks EID, sequence, magic and response tag. Its original implementation accepts CAL status too loosely: it returns success even for unknown/error statuses. Offline response validator is deliberately stricter: exact28-byte PHY response, tag CAL1 size16, count1/version1/body20, expected event81/82 and matching bounded EID/sequence; FORCE only SUCCESS0, BACKUP SUCCESS0 or RECAL2. This stricter tagcount/version/length/reserved policy follows the declared ABI but has not been validated against actual PHY firmware response bytes. Capture mismatch as refusal, not evidence the action failed electrically. Never promote Linux's unconditional CAL-tag success into calibration success.

FORCE-success or BACKUP-recal requires a returned EMI region satisfying offset=(address&ffffff), length>0 and overflow-safe containment within the owned CONN extent. Source `pre_cal.c:89–115` copies returned range for backup;152–153 exports offset+4 and2048 RFCR bytes separately. Validation here does not map/copy EMI or establish MPU permissions; a later backup export must additionally bound offset+4+2048 against its actual owned region, not assume u4EmiLength proves that. A missing/invalid runtime backup cannot justify choosing BACKUP to avoid calibration.

Source timeout constants `include/config.h:564–568` are wait interval50000 and response timeout5000; transport must preserve units via actual nicRxWaitResponseByWaitingInterval implementation and retain finite deadline/no blind replay after uncertain submission. This candidate has no wait or retry loop.

## Co-antenna and PCCIF actions

Saved WIFI ucSupportCoAnt[243] is0. `soc3_0.c:2543–2577` therefore performs no coant PMIC call with these exact bytes. This does not permit substituting a false zero if NVRAM changes. If nonzero on the selected below5.4 path, it calls KERNEL_pmic_ldo_vfe28_lp(8,0,1,0) once, not an arbitrary rail-enable approximation. The disable counterpart2580–2593 uses(8,0,0,0). `common/connectivity_build_in_adapter.c:291–296` forwards to selected PMIC API. Saved .config selects MT6359P, not MT6359. MT6359P `pmic_lp_api.c:552–565` only updates op_mode for users<=SRCLKEN2; user8=SRCLKEN8 therefore skips mode. It uses OP_EN at1b8e bit8 and OP_CFG at1b94 bit8 (shift6) via read-modify-write/readback, enable1/config0. MT6359 (non-P) addresses differ: do not copy1b8c/1b92. No such write is needed or implemented here.

`soc3_0.c:2616–2640` PCCIF-on literally writes10003314=0 then1 to announce Wi-Fi power to modem. Clock control comment is inactive; no100010c4 gate write belongs in this hook. Off2642ff writes10003314=0 then1024c014=ff. These are separate persistent modem/coexistence effects requiring explicit lifetime/ownership/error and teardown policy, not reversible arbitrary register preservation. Linux on helper ignores individual wf_ioremap_write errors and returns0; native implementation must capture operation results and stop on uncertainty. Do not emit PCCIF-on for a PHY failure or invent modem readiness from a successful write. No PCCIF action is executed by this candidate.
