# Independent low-DMA source audit

Selected Android pin04d00c2565764c3922c9b4826b5acff1106e533f. Source-only; no mapping, DMA, reservation or device operation performed.

The low-address requirement is concrete. `chips/soc3_0/soc3_0.c:973` selects `u4DmaMask=32`. AXI `axi.c:468-469` passes that mask to `dma_set_mask_and_coherent`; chip `soc3_0.c:550-554` enables pdma_addr_ext only if mask>32, therefore selected false. `hal_pdma.c:1906-1910,2535-2541,2627-2633` splits low32/optional high descriptor fields. Presence of optional high fields is not authorization to enable them or truncate native addresses. Every ring base and every packet/command/RX buffer address plus full extent must fit the selected32-bit DMA range; XNU's managed142000000..180000000 allocations fail that requirement. Virtual allocation, remap-window target and physical firmware address are not interchangeable DMA addresses.

`dtb/nord2/live.dts:1108-1114` wifi-reserve-memory describes sizef20000, alignment1000000, alloc-ranges40000000+c0000000end, no-map/shared-dma-pool. This is a dynamic allocation policy, no fixed reg. AXI `axi.c:555-577` resolves memory-region size, `585-599` aligns suballocations8bytes, `602-620` uses KAL_DMA_ALLOC_COHERENT and its returned DMA addresses. It does not establish a currently free fixed iOS pool base or identity IOVA=PA for a newly invented carveout. A low range outside XNU allocator is necessary but insufficient; current-boot loader fixed reservation must check firmware/DT reservations and all selected fixed aliases, retain buffer lifetime, and explicitly establish selected WFDMA bus-address translation/cache ownership. Never borrow MCIF/CCCI or overlap CONN firmware spans.

The existing source region27SET protects only CONN8fb00000..8ff4ffff. Its accepted result and observed ROM_DONE do not establish permissions for an unrelated low DMA pool. Derive actual source MPU/IOMMU policy for the chosen pool/master path; do not install arbitrary new region policy merely because getter is unsupported. Dynamic DT shared-pool allocation alone also does not document a required secure MPU setter for every possible low range. Distinguish an actual applicable policy requirement from unknown global raw state.

Concrete next design review: one current-boot pool claim (base,size,source,valid plus non-overlap proof), all ring/descriptor/buffer layout extents checked for overflow/alignment/<4GiB, one AP cache attribute/alias contract, source-correct WFDMA address encoding, ring ownership and producer/consumer barriers. CPU stores/readback do not prove device DMA visibility; completion must be actual owned ring status. Claim record must not be repurposed from the ROM CONN24B record. Retain all buffers until DMA quiescence is proven; ambiguous enable/submit/timeout means manual reset, no allocator reuse. Coordinate concrete pool choice with pool author before implementing hardware writes.

The main-fw transport plan correctly groups patch+fiveN9spans+both finish results+SW_SYNC0ready into a meaningful firmware-ready milestone. Dynamic copies alone cannot replace completion transport. No mainN9ready, scan, association, packets or iOSWiFiinterface has yet been observed.
