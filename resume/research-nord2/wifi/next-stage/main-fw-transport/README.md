# Nord 2 next Wi-Fi milestone: patch, N9 image, firmware-ready

Private design only. Source pin: `../nord2-current-kernel` commit `04d00c2565764c3922c9b4826b5acff1106e533f`, selected `gen4m/Android.mk:8-17` (`CONNAC2X2_SOC3_0`, AXI). This is conditional on a **confirmed** current-boot ROM_DONE result; the parent ROM test result is unknown at preparation time. No code here performs MMIO, SMC, DMA, firmware execution, scan, or an iOS network publication.

## One useful combined hardware step

Build one new, opt-in, fresh owner that starts only after the prior ROM helper's actual same-boot native receipt and `ROM_DONE=0x1d1e`, and retains its existing CONN carveout/policy/native buffer lifetime. Its success criterion should be all of: patch copy + patch-finish command/result, five main N9 region copies + firmware-finish command/result, and selected `SW_SYNC0` ready bits. Keep AP/WF access votes for the entire sequence; previous ROM helper ended with both votes asleep, so it cannot be reused as an awake object. Failure after any write, DMA submit, or firmware command is uncertain: retain memory/power/owner state for manual reset, never replay or claim rollback. Source startup uses interrupts disabled and FW download polling (`common/wlan_lib.c:1260-1303`); interrupt routing is not a prerequisite for this *first* ready check, but polled WFDMA RX/TX is.

Selected source order is ROM EMI placement before CPU release (`chips/soc3_0/soc3_0.c:2295-2375`); after ROM, pre-cal prepares HIF/Tx/Rx, enables FWDL cut-through, disables interrupts and downloads the patch (`chips/common/pre_cal.c:985-1025`). The main startup path downloads patch then N9 image and polls ready (`chips/common/fw_dl.c:2310-2385`, `common/wlan_lib.c:1280-1315`). `CFG_ROM_PATCH_NO_SEM_CTRL=1` omits the patch semaphore exchange; it does **not** omit the patch. `CFG_DOWNLOAD_DYN_MEMORY_MAP=1` selects direct remap for these unencrypted regions (`gen4m/Makefile:131-146,428-430`, `chips/soc3_0/soc3_0.c:2970-3110`). The chip descriptor explicitly sets `is_support_cr4=FALSE`, `is_support_wacpu=FALSE` (`soc3_0.c:1137-1150`), so the selected N9 path has no CR4 image stage.

## Exact payload and address plan

Reuse `shim/nord2-xnu/wifi_firmware.c` `nwf_load`: its four retained vendor blobs are full-file SHA-256 authenticated; main is `blobs[0]` (973,648 bytes, SHA `c8689aace6c3b2f8d9ee49be358452e4d7359748ba2d564935e38cff0faafbf2`), patch is `blobs[1]` (5,726 bytes, SHA `4fc5a6bcbbdd0a12c48a61a26768bc48c82da61f60834817d1857e21b3750`). The private `main_fw_layout.c` only checks the fixed structural format and provides bounded spans; it **does not** authenticate arbitrary supplied pointers. The native caller must retain and tie those pointers to the same successful `nwf_load` and ROM ownership object. The source layout is `include/chips/fw_dl.h:167-195,235-243`, `chips/common/fw_dl.c:2050-2140`, `chips/soc3_0/soc3_0.c:2970-3110`, with saved decoded evidence in `research/nord2/wifi/firmware/download-layout.json`.

The tail has 116 release-info bytes, five 40-byte region records and a 36-byte common record; no sixth data span. All five section feature bytes are `0,0,0,0x80,0x80`, meaning the last two use EMI; there is no valid-RAM-entry bit, so the FW start override/address are both zero. Do not reinterpret the `0xf0...` addresses as arbitrary DRAM: `wlanDownloadEMISection` and the existing fixed CONN claim define the physical correspondence. All EMI spans, date code and prior ROM spans are inside the existing `0x8fb00000+0x450000` claim; validate disjointness against the ROM receipt and any DMA pool before writes. The source's patch v1 header is 30 bytes; `ucCheckCrc=0` for the completion command, so the selected command does not prove an additional patch CRC (`chips/common/fw_dl.c:1016-1106`).

For non-EMI spans, source `downloadImgByDynMemMap` writes `ap2wf_remap_1` with **each exact target** then copies bytes through `0x7c500000`; AXI has no PCIe remap operation (`chips/common/cmm_asic_connac2x.c:2018-2065`). Its AXI static map is chip `0x7c500000` to bus offset `0x500000`, length `0x10000` (`chips/soc3_0/soc3_0.c:234-283`); the remap register is `0x18001120` (`include/chips/coda/soc3_0/conn_infra_cfg.h:63-65`). Each dynamic span is under 64 KiB. Native code must prove the relevant XNU mapping/alias, serialization, remap ownership and restore/retain semantics; a CPU pointer to literal `0x7c500000` is not established by the parser. EMI writes require source-consistent cache visibility and readback/barrier policy from the existing native ROM owner; firmware already executing means uncertainty cannot be undone by restoring bytes.

After patch bytes/date become visible, submit `INIT_CMD_ID_DYN_MEM_MAP_PATCH_FINISH=0x40` with four-byte payload `ucCheckCrc=0`; wait for `INIT_EVENT_ID_CMD_RESULT=1`, matching sequence and status zero. Then copy all five N9 spans and submit `INIT_CMD_ID_DYN_MEM_MAP_FW_FINISH=0x41` with eight-byte payload `{override=0,address=0}`; wait for its result before polling ready (`chips/common/fw_dl.c:1016-1110,1469-1535,1669-1790,2214-2280`). Selected source's patch caller discards the completion helper's return at `fw_dl.c:2438-2445`; the new owner should explicitly require the result rather than propagate that omission. `main_fw_layout.c` validates a supplied 24-byte RX descriptor + 8-byte init event + 4-byte result frame (EID, sequence, command ID and status), but a matching buffer is only meaningful when a correctly owned RX ring delivered it. It does not build a TX descriptor or imply command submission.

The ready register is `SOC3_0_SW_SYNC0 = 0x7c0600f0`, selected shift zero and `WIFI_FUNC_NO_CR4_READY_BITS=BITS(0,1)` (`include/chips/soc3_0.h:83-85`, `include/chips/cmm_asic_connac2x.h:108-110`, `include/nic/mt66xx_reg.h:1269-1270`, `soc3_0.c:1137-1146`). Source polls it with bounded timeout/delay (`common/wlan_lib.c:1646-1718`, `include/config.h:553-560`). A ready-bit pass is a **firmware-ready** observation, not scan or association.

## Native transport prerequisites to implement before one combined image

1. Bind a fresh post-ROM owner to the same current claim, accepted region-27 policy and retained authenticated buffers. Show ROM receipt, CPURELEASE attempted/released, `ROM_DONE`, no competing old `nawa`/`nwsa` object, and a new scoped AP/WF wake/readability lifetime. Decide how to keep the running WFSYS powered and protected while AP/WF access votes are acquired; do not repeat a cold power sequence or release inherited/unknown resources.
2. Implement bounded source-specific AXI AP2WF remap and CONN EMI writers, per-span visibility/readback and explicit write uncertainty. Native map must correspond to `soc3_0_bus2chip_cr_mapping`, not a guessed physical aperture. Preserve the four-file verifier's lifetime and claim/protection policy.
3. Implement **polled** WFDMA1 host TX ring 17 for init commands and WFDMA1 host RX ring 0 for init results, including chip/HIF init, source descriptor format, ring base/count/index/enable, DMA address translation, coherent/cache maintenance, DMA ownership, bounded producer/consumer waits, and exact command framing. Ring 16 is the FWDL port, not these dynamic-map copies; `u2TxInitCmdPort` selects ring 17 (`chips/common/cmm_asic_connac2x.c:110-175`, `include/chips/cmm_asic_connac2x.h:156-157`, `chips/soc3_0/soc3_0.c:291-325,924-985`). `HIF_IMG_DL_STATUS_PORT_IDX=1` selects the RX event port (`os/linux/hif/common/include/hif_pdma.h:185`). Manual prefetch and AXI BID-bypass setup are source operations (`soc3_0.c:790-878`); do not assume reset pointers or DMA ownership are safe from a late kernel hook.
4. Preserve startup obligations that the selected driver performs around image download: driver own/HIF init and FWDL cut-through, Tx resource init, selected PHY action and coexistence hooks if their actual chip capability/board configuration requires them (`common/wlan_lib.c:1180-1315`, `chips/common/fw_dl.c:2310-2385`). These are not safely replaced by the parser. The first implementation can stop on an unresolved hook and retain state; do not claim ready by bypassing it.

Once the transport is implemented and host-fault tested, one opt-in image can make all seven exact copies, command/result exchanges and ready poll in one run. Bounded captured-only logs should report first failed stage, per-span target/readback counts, TX/RX ring ownership and sequence/status, final `0x7c0600f0`, and retained-owner/manual-reset state. No extra MMIO after final AP sleep. **Do not run this image based on an unconfirmed ROM milestone.**

### DMA address-width finding

The selected SOC3_0 descriptor sets `u4DmaMask=32` (`chips/soc3_0/soc3_0.c:973`). AXI setup passes `DMA_BIT_MASK(32)` to `dma_set_mask_and_coherent` (`os/linux/hif/axi/axi.c:444-473`), and WFDMA setup leaves `pdma_addr_ext_en=0` because the mask is not greater than 32 (`soc3_0.c:530-558`). TX/RX ring base programming writes only low 32 bits (`os/linux/hif/common/hal_pdma.c:2205-2233,2278-2293`); the helper that writes ring-base high bits returns immediately when `u4DmaMask<=32` (`chips/common/cmm_asic_connac2x.c:597-650`). TX/RX descriptors *contain* high address fields, and common code populates them under `CONFIG_PHYS_ADDR_T_64BIT` (`hal_pdma.c:1902-1915,2532-2543`), but the selected DMA mask and extension gate mean those fields are **not** a source-backed high-address solution for this chip. The native owner must prove a device-visible DMA/bus address below 4 GiB for every ring and buffer; a high XNU backing PA could work only through an independently proven IOMMU mapping to such an address. Do not truncate the current XNU `0x142000000..0x180000000` allocator PA to 32 bits.

The saved live DT has a separate dynamic `wifi-reserve-memory` shared DMA pool, size `0x00f20000`, `alloc-ranges=0x40000000+0x80000000`, and `no-map` (`dtb/nord2/live.dts:1108-1114`; decoded in `research/nord2/wifi/next-stage/memory-ownership/evidence.json`). This is distinct from the fixed current-boot CONN firmware claim. It provides an Android allocation **policy**, not a proven current iOS reservation/base or permission to put descriptors in CONN ROM space. Selected AXI source preallocates coherent ring/command/event buffers from this Wi-Fi reservation (`os/linux/hif/axi/include/hif.h:98`, `os/linux/hif/axi/axi.c:555-733`). A native DMA pool needs its own current-boot reservation, non-overlap with XNU/CONN/modem, mapped-bus-address proof and cache policy; the present evidence does not supply a safe base by itself.

After firmware-ready, reaching userland Wi-Fi still needs selected gen4m capability/event and scan command implementation, RX/TX packet rings, station/key flow, and an iOS16 service/ifnet/Apple80211-facing bridge. The Topaz source audit (`research/nord2/wifi/topaz-reference/report.md`) is useful for a hardware-independent asynchronous ready/scan/join boundary and low-32-bit DMA lesson; its Qualcomm CE/HTC/WMI transport is not usable here, and its published checkout does not prove an iOS wifid bridge.
