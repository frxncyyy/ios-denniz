# Source-sized low-DMA ownership candidate

Private offline candidate, selected Android source `../nord2-current-kernel` commit `04d00c2565764c3922c9b4826b5acff1106e533f`. Current ROM hardware reached same-boot ROM_DONE in the parent's initial capture; this design is not integrated or a DMA/firmware-ready result. It performs no SMC, MMIO, DRAM mapping, DMA or firmware operation. The proposed range is an **explicit iOS fixed policy**, not a recovered LK allocation.

## Fixed claim and exact first slice

Choose `0x90000000..0x90f20000` (base `0x90000000`, size `0x00f20000`, 16-MiB alignment). The original live FDT's `/reserved-memory/wifi-reserve-memory` is `shared-dma-pool`, `no-map`, size `0xf20000`, alignment `0x1000000`, alloc-ranges `0x40000000+0x80000000`, but has **no reg** (`dtb/nord2/live.dts:1108-1115`, `mt6893.dts:765-772`). Its phandle is the `/wifi@18000000` device's `memory-region` (`live.dts:7985-7992`). The original FDT therefore supplies a source-sized allocation policy, not current fixed placement. The chosen candidate lies inside its allowed range, starts `0xb0000` above the selected CONN claim end `0x8fb00000+0x450000=0x8ff50000`, and is below the next saved fixed reservation beginning `0x9fa00000` (`memory-ownership/evidence.json`). It is wholly below 4 GiB and outside the loader/ADT XNU allocator window `0x142000000..0x180000000` (`shim/nord2-xnu/loader.c:40-41,547-548,605-608`; `tools/mkadt-nord2.py:29-30,65-66`). These facts establish a defensible *candidate*, not hidden-master absence or MPU permission.

The selected AXI driver preallocates coherent descriptors/buffers from this separate Wi-Fi reserved-memory pool (`os/linux/hif/axi/include/hif.h:98-105`, `os/linux/hif/axi/axi.c:555-733`). It sets `u4DmaMask=32` and disables WFDMA address extensions (`chips/soc3_0/soc3_0.c:530-558,973`); Linux applies `DMA_BIT_MASK(32)` (`os/linux/hif/axi/axi.c:444-473`). Generic descriptors have high fields, but ring-base high bits are skipped for `u4DmaMask<=32` (`chips/common/cmm_asic_connac2x.c:597-650`). Without a separately proven low IOVA mapping, native WFDMA must use device-visible addresses entirely below 4 GiB. The fixed candidate uses physical==bus only **if** current platform routing is established; no truncation of high XNU PA is allowed.

For the first *firmware-ready* transport, reserve only the first `0x20000` of the full pool for the source-size command/event rings. Selected SOC3_0 compiles `CONFIG_MTK_WIFI_HE80`, `CFG_TRI_TX_RING=0` (`gen4m/Makefile:131-147,178-183`), giving `TX_RING_SIZE=1024`, `RX_RING1_SIZE=16`, and 16-byte TX/RX descriptors (`os/linux/hif/common/include/hif_pdma.h:111-150`). `halWpdmaAllocRing` allocates the event ring with 16 descriptors and `RX_BUFFER_AGGRESIZE=3840` buffers (`os/linux/hif/common/hal_pdma.c:1945-2000`); SOC3_0 maps that software event ring to host WFDMA1 RX ring0 (`chips/soc3_0/soc3_0.c:365-414`). The source AXI TX command buffer is 4096 bytes (`os/linux/hif/axi/include/hif.h:104`); source preallocates one buffer per 1024 TX cells, but the narrowed native design permits **exactly one outstanding init command**, waits for TX DMA reclaim and its result, then reuses one buffer. This is a deliberate software restriction to host-test, not a claim of source-identical allocation topology.

|First-slice use|Offset|Bytes/stride|End|
|---|---:|---:|---:|
|Host WFDMA1 TX ring17, 1024 descriptors|`0x00000`|`0x4000`|`0x04000`|
|Host WFDMA1 RX event ring0, 16 descriptors|`0x04000`|`0x0100`|`0x04100`|
|Guard/padding to page|`0x04100`|`0x0f00`|`0x05000`|
|One TX init-command buffer|`0x05000`|`0x1000`|`0x06000`|

Raw source-size storage is `1024*16 + 16*16 + 4096 + 16*3840 = 82,176` bytes. The page/slot-aligned layout occupies `0x16000=90,112` bytes and rounds to the smallest 64-KiB-aligned slice of `0x20000`. The rest of the full `0xf20000` claim remains untouched until a separately reviewed data-ring/scan owner uses it. Do not shrink the **claimed** MPU region to `0x20000`: the selected platform locks its Wi-Fi DMA region and a later enlargement would be unavailable without reset. The full claim also avoids another loader/ADT ABI change before data-ring work.

## Separate region-18 SET contract

Selected `os/linux/plat/mt6893/plat_priv.c:289-313` calls `mtk_emimpu_init_region(&region,18)` over the Wi-Fi reserved pool, sets AP domain0 and CONN domain2 to `MTK_EMIMPU_NO_PROTECTION=0`, leaves the other fourteen domains at initialized `MTK_EMIMPU_FORBIDDEN=5`, requests `MTK_EMIMPU_LOCK`, then calls the setter. Source `drivers/memory/mediatek/emimpu_old.c:690-727,819-860` packs group **1 then 0** in 64-KiB units and ignores `smc_res` when returning. This is distinct from ROM's accepted region27; region27 does not cover the DMA pool. For the proposed fixed range, private `ndp_region18_set_intent` emits:

|Group|x0|x1 action|x2 start/region|x3 inclusive end/group|x4 APC/lock|
|---|---|---|---|---|---|
|1|`c200050b`|0|`12009000`|`010090f1`|`00b6db6d`|
|0|`c200050b`|0|`12009000`|`000090f1`|`80b6da28`|

`x5..x7=0`. The backed-up monitor action0 contract is already source/disassembly-pinned in `monitor-abi/region27-source-policy.md`: validator may reject, group0 forces software lock, and group1 success followed by group0 failure leaves partial policy. Region18's validator/lock state is **not** established by region27 success. Actual native code must capture both full `x0..x3` SMC return tuples, require `x0=0` for each before any pool write/DMA submit, set an attempted/possibly-locked latch **before** each call, and retain/halt on nonzero or uncertain result without retry, CLEAR or rollback. `ndp_both_raw_zero` checks only the x0 status registers; other returned registers are captured observations, not invented status gates. It is not a permission callback or effective policy readback. The selected Linux helper also ignores protection-setter failure (`plat_priv.c:300-314`), which the iOS owner should not emulate.

## Loader, ADT and native insertion

Extend the existing *opt-in* current-boot loader claim path, before payload relocation and before XNU, with a new exact `/chosen/nord2-wifi-dma-claim` property of 24 little-endian bytes: `base:u64`, `size:u64`, `source:u32=3`, `valid:u32=1`. Generator emits zero-filled placeholder; loader fills only after `ndp_fixed_claim_from_fdt` succeeds on the **original** current-boot FDT. That parser calls the existing hardened `nrc_ios_fixed_claim_from_fdt` unchanged, then separately verifies root/reserved-memory 2-cell encoding and empty ranges, one Wi-Fi dynamic node with exact source size/alignment/range/no-map/compatible/phandle, matching `/wifi@18000000 memory-region`, containment in original `/memory reg`, and nonintersection of every explicit reserved-memory child `reg` and FDT memreserve entry with the proposed range. It rejects duplicates and malformed/overflowed ranges. The loader must additionally check the *physical location* of the original FDT against both CONN and DMA ranges, plus its stock Image/payload/log/stacks and every target segment against the pool; the pure FDT parser has no knowledge of the FDT's PA. The low range remains outside all XNU allocators by the chosen high `dram-base/size`, but an ADT claim is only a record of the explicit iOS policy, not a memory write or hardware lock. No active loader/ADT file is changed by this candidate.

In the native owner, decode that exact claim and tie it to the same boot's CONN claim, ROM/native receipt and authenticated firmware blobs. Compare against bootargs and current ADT `dram-base/size`; reject any overlapping fixed alias. Map the pool once with one chosen CPU cache attribute; the reviewed XNU `ml_io_map` path maps low RAM outside the high XNU DRAM window as Device-nGnRnE (`rom-native-binding/README.md:14`, selected `osfmk/arm/pmap/pmap.c:5652-5665`), and the initial/fixed XNU mappings inventory in `memory-ownership/REPORT.md` contains no `0x90000000` alias. Preserve that no-WB-alias invariant across the linked image. Use aligned 32-bit descriptor access and source-ordered barriers before producer-index writes and after completion observation; do not assume ordinary `memcpy`/cache maintenance against a Device mapping is safe. A later native adapter must prove AP/CONN EMI visibility and WFDMA bus routing under the actual region18 return contract. No IOMMU programming or speculative MMIO probing is proposed.

Selected `soc3_0asicConnac2xWfdmaManualPrefetch` and `halWpdmaInitRing` touch/reset more than ring17/RX0 (`soc3_0.c:790-878`, `os/linux/hif/common/hal_pdma.c:2140-2300`). A first owner cannot blindly invoke that broad sequence in a late XNU hook. It needs proven inherited WFDMA idle/sole ownership, or a source-subset initialization of only owned rings plus a separately justified global prerequisite. That work, native region18 acceptance and bus-address/coherency proof are **implementation blockers**, not reasons to split patch/main into tiny hardware probes. Once discharged and host-fault tested, one opt-in image can proceed through the seven image spans, two command/result exchanges and `SW_SYNC0` ready poll described in `README.md`. It still cannot claim scan, RF traffic or an iOS network interface.

Host `test_dma_pool.c` exercises actual saved `dtb/nord2/live.dtb`, FDT header/size/alignment/alloc-range/phandle/fixed-reservation faults, claim wire validation, exact group order/payload/raw-status gate and bounded slice. Both private C files compile for ARM64. No current live FDT or hidden-master status was observed by this offline test.
