# Private SOC3_0 WFDMA transport candidate

This package contains a callback initializer and bounded polled command transport, not an installed XNU driver. No hardware, SMC, physical memory, CI or device operation was performed. Android source is pinned to `04d00c2565764c3922c9b4826b5acff1106e533f`, under `drivers/misc/mediatek/connectivity/wlan/core/gen4m/`. The separate frozen `preflight/` package remains unchanged and authoritative for the next read-only hardware diagnostic. The older `nwt_preflight` is only an unsupported-initializer test model and must not replace it.

`nwi_prepare` consumes the actual completed pool-probe receipt and exact claim. It plans four configured TX rings (hardware 0, 2, 17, 16) and five RX rings (DMA0 rings 0–3 and DMA1 event ring 0). Ring 17, event descriptors, event buffers and the single command buffer retain the existing first-128-KiB layout. Remaining source-used rings and their buffers occupy the rest of the full region18-protected pool; they are disjoint and below 4 GiB. This deliberately requires the full source-sized claim, not merely permission to touch the probe subpool.

`nwi_initialize` first captures both DMA engines and all 27 affected rings. Known inherited state refuses without writes; unknown reads halt. It refuses existing defined interrupt enables before mutation. It obtains driver ownership through LPCTL write 2 and bounded bit2-clear readback, then performs the source DMASHDL 99 RMW operations, buffer/descriptor initialization, disable/idle/index reset, source ring programming, 42 prefetch operations, global configuration, DMA enable and dummy handshake. Every operation requires fresh ownership; after driver ownership, LPCTL is checked before each initializer backend operation. Any uncertain write or timeout retains state and requires reset; replay is rejected.

This is a **polling derivative** of the Linux interrupt lifecycle. It preserves the source interrupt-clear step but omits interrupt SET. Defined INT_ENA fields must be zero at entry and remain zero before enable; raw values are captured and reserved bits ignored. The CODA field masks are `0x33f800ff` for DMA0 and `0x7d37ffff` for DMA1. The external native owner must also keep the platform IRQ disabled. There is no XNU handler in this candidate. It must not claim source-identical interrupt behavior.

`nwt_capture` accepts a complete command frame, expected EID and caller-owned output buffer. It publishes command bytes and a descriptor with visibility callbacks before TX CIDX, waits for both TX DIDX and DDONE, waits for RX DIDX and DDONE/LastSec0, copies only the descriptor-bounded event, checks packet type/EID/sequence, and rearms the owned RX slot. It records descriptor, MAC RXD and embedded INIT counts. The caller validates command-specific payload before another command and latches halt on rejection. `nwt_exchange` adds selected CID40/41 finish-result status/CID validation. The PHY adapter can use CID8 with a 464-byte frame and a 60-byte response without adding a fake permission callback.

The selected driver ignores embedded INIT length equality. The implementation therefore requires enough owned descriptor bytes for parsed fields and an output size within the 3840-byte owned buffer, while capturing raw counts. It does not assert that INIT count equals 12 or 36. No real event has yet been captured. RXINFO/DW3 is checksum status, not a high pointer; it may be nonzero. DW2, containing pointer extension/second segment, must be zero for the selected low32 single-segment policy.

## Validation and remaining integration

ASan/UBSan tests cover all initializer callback fault positions, committed failing writes, no callbacks after error, no replay, ownership loss, inherited refusal, descriptor/buffer layout, visibility, CID40/41 exchange and generic PHY-sized capture. Focused freestanding ARM64 compilation covers initializer, scheduler and transport. See `test-results/` and the manifest for exact pins and counts. This is a host callback model, not proof of physical DMA visibility or hardware behavior.

The finite remaining implementation boundary is the fresh native owner and backend: actual same-boot ROM/pool receipts, AP/WF votes, clock/readability and driver ownership, stage-allowlisted registers, retained full-pool mapping, barriers/cache contract, disabled platform IRQ and captured-only diagnostics. The callback initializer currently keeps driver ownership and DMA state retained; it does not implement teardown or permit sleep after enable. The parent and PHY agent own authenticated patch/main span placement, calibration/coexistence ordering and FW_READY. Those must be connected to this actual initializer receipt before a combined image can run. Firmware readiness is not networking.
