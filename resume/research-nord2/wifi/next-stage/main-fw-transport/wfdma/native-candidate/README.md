# Private fresh main-firmware lifetime

The native wrapper and coordinator are now concrete source candidates. They add no production hook, CI or device operation. The proposed whole `sweet_touch` copy has one new call immediately after `nppa_after_rom`; it compiles with CI-derived ARM64 flags and the normal board guard. The parent may normalize includes to flat `wifi_main_*` names; do not text-include C implementation files.

Include order is existing ROM binding, existing pool binding, `wfdma_bind.inc`, then `main_bind.inc`. Callback initializer/transport, layout, firmware and PHY implementations are separate translation units. `nord2wifimain=1` is the distinct default-off gate and requires `nord2wifirom=1` and `nord2wifidma=1`. Existing `nord2wififw=1` is unchanged. Prepare is sleepable and runs at this input-thread hook before fresh AP/WF votes; it maps only MMIO pages, retains the accepted pool mapping, and calls the peer's authenticated firmware/board preparation. It does not copy firmware in preparation.

`nwfn_native` owns a fresh AP/WF lifetime. It checks exact retained ROM/pool receipts and the fixed current claim, snapshots unique HOST votes, performs source ACK/readability/clock/IRQ and running-CPU/power/protection/ID/ROM proofs, then calls the reviewed initializer. It never invokes old sleeping `nppa` or `nrpa` callback objects. Each native callback checks ownership; after driver-own acquisition this includes LPCTL. The exact prepared ring, command-buffer and transport identities are pinned. Descriptor/buffer callbacks allow only the current owned slot or source initialization ranges inside the full region18 pool, never MCIF or arbitrary DRAM. Register writes are limited by initialization phase and source plan/value. Coherent fault bits20/21 are polled during later native operations as well as by reviewed transport.

The pool remains the accepted low-PA `ml_io_map` Device mapping outside managed DRAM. No cached alias is introduced; volatile byte copies plus `dsb sy` implement the explicit visibility callback. Physical DMA visibility remains untested. The new read-only GIC guard requires selected Wi-Fi INTIDs407/410 disabled in GICD_ISENABLER12; saved board DT `dtb/nord2/live.dts:7985–7989` gives SPIs375/378 and `1182–1191` gives GICD PA0xc000000. No GIC register is written. Peripheral INT_ENA defined fields must remain zero. This is a polling derivative, with no claimed XNU IRQ handler. The selected board IRQ identity is a source-policy assumption; peer current-FDT validation supplies the board provenance, not a new IRQ registration.

Coordinator order is preparation → fresh wake/WFDMA → two patch spans → actual CID40 result → real FORCE_CAL/validated event/retained EMI backup → selected PCCIF → five N9 spans → actual CID41 result → bounded FW_READY. The peer firmware and PHY implementations own their source checks. `nwfn_finish_command` uses retained TX72/RX3840 storage, preserving reviewed finish-result semantics without a 4-KiB caller-stack event buffer. No embedded INIT length equality is invented.

Any uncertain stage shares native/initializer/transport/firmware/PHY halt state and stops later stage calls. After captured-only diagnostics, owned or mutated radio/DMA uncertainty calls `panic` and requires manual reset. Preparation failures without owned/mutated resources may return to iOS. A complete inherited-state refusal before mutation balances source sleep; AP literal zero is final hardware access and reporting uses captured state only. Success keeps driver ownership, AP/WF votes, descriptors, buffers and firmware memory retained. There is no teardown, automatic replay or sleep after DMA enable. FW_READY is not networking.

The native ASan/UBSan host model exercises actual initializer and actual transport through synthetic register/DMA effects, default-off and preparation without MMIO, command order40→8→41, identity and memory bounds, IRQ refusal, inherited balanced sleep/no later MMIO, bounded ACK/clock failures, every coordinator child-failure boundary, common halt and panic selection. Firmware span/PHY child functions are test stubs only for coordinator order; peer tests cover actual payload/authentication/copy semantics. Host `panic` records terminal selection and returns solely for assertions; real kernel `panic` does not return. No host test executes hardware.

`compile-command.json`, `compile.log`, `stack-native.txt` and object pins record the focused whole-TU check. The native finish helper uses64 stack bytes in that build; native contexts and event buffers are retained globals. Callback stack samples are separately captured; the initializer and command exchange are sequential, not nested. A full final linked artifact and hardware review remain necessary before execution.
