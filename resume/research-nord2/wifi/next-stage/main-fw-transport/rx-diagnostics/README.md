# Private captured-only RX contingency

This separate package is contingency diagnostics, not an activation or request for CI/hardware. No RX response has yet been observed. The source audit at sibling `rx-response-audit/report.json` distinguishes compatible ring/layout facts from extra strict native contracts and timeout differences. Nothing here changes any accepted descriptor, byte count, header, sequence, status, CID, PHY policy, polling budget, memory visibility, ownership, halt, rearm or replay behavior.

Append-only nwt_state fields record the current expected RX descriptor PA and buffer, expected EID/sequence, latest successfully read DIDX, latest successfully copied descriptor4words, and bounded first INIT event metadata. Every byte comes from already performed reads/copies: there is no extra backend call, descriptor re-read, memory read, callback, reset, IRQ acknowledgment or payload dump. Validity bit0 means prepared expected identities, bit1 means successful DIDX read, bit2 means successful descriptor copy, bit3 means at least32 frame bytes were actually copied (type/EID/sequence), bit4 means at least34 bytes with packettypee000 and EID1 (command-result status/CID). Status/CID stay invalid for PHY EID5 and cannot expose its calibration/TLV data. Embedded byte counts continue to use the existing captured fields without a new equality rule.

Failure reason refers to the transport RX admission stage only:0 none,1 out-of-range DIDX,2 existing descriptor/rearm-builder rejection,3 existing type/EID/sequence rejection,4 RX timeout,5 coherent guard failure in RX/prerearm,6 failed existing callback during RX/rearm. Higher-layer status/CID/PHY semantic failure remains diagnosed by existing native error/status fields; it is not mislabeled a transport-header refusal. Callback errors preserve the original underlying transport error and no later callback occurs. A failed callback does not mark its output valid, even if a synthetic callback writes before returning failure. A DDONE0 descriptor is captured before waiting, not parsed as a completed packet.

Captured-only coordinator lines are `NORD2 WIFI MAIN RXDESC:`, `NORD2 WIFI MAIN RXWORDS:`, `NORD2 WIFI MAIN RXHEADER:`. They contain pointer/count/status metadata only, no MAC/SSID/command/firmware/calibration payload. Existing30-second failure drain and TX writeback diagnostics remain. Header additions require all consumers to rebuild together. Proposed canonical files: `wifi_main_transport.c/h` and `wifi_main_bind.inc`. No other active or frozen file was edited.

ASan/UBSan tests retain the same52 successful-exchange callback count and all52 callback-fault cases, preserving no-replay/no-rearm behavior. New cases validate successful metadata, wrong event sequence, short32-byte header without status/CID, PHY60-byte event without command-result payload capture, bad RX pointer before frame copy, wrong DIDX, absent event/DDONE timeout and prerearm coherent error, with exact validity/reason assertions. Prior measured-zero TX regression remains unchanged. Local whole/transport ARM64 tests are modified CI-derived invocations with extra include directories; they are not exact normal generated-source compilation. Parent decides whether any future evidence warrants integration and performs actual sibling-context checks separately.
