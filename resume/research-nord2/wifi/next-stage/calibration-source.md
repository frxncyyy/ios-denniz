`CFG_SUPPORT_NVRAM=1` (`gen4m/include/config.h:880`). If NVRAM is unavailable, `glLoadNvram` returns without setting `fgNvramAvailable` (`gl_init.c:1580-1595`), and `kalIsConfigurationExist` simply reflects that flag (`gl_kal.c:5761-5778`). The post-firmware-ready path skips `wlanLoadManufactureData` with a warning, rather than aborting startup (`common/wlan_lib.c:1113-1121`). When available, `wlanLoadManufactureData` sends the manufacturing parameters to firmware as `CMD_ID_SET_NVRAM_SETTINGS`, using TLV fragments for a chip that supports them (`wlan_lib.c:5272-5450`). Thus the source has a boot fallback, but omission would lose device-specific regulatory/band/power/calibration configuration; it is not a sound target for functional Wi-Fi.

MAC provenance is conditional. With `CFG_TC1_FEATURE`, `glLoadNvram` and `kalRetrieveNetworkAddress` call the TC1 factory MAC reader; otherwise they use `WIFI_CFG_PARAM_STRUCT.aucMacAddress` from the NVRAM buffer (`gl_init.c:1601-1609`, `gl_kal.c:5080-5102`; Makefile:484-489 selects the TC1 flag from `CONFIG_MTK_TC1_FEATURE`). The firmware NIC-capability event also provides an embedded MAC and validity bit (`wlan_lib.c:4872-4887`). `wlanUpdateNetworkAddress` prefers a valid host-supplied address, falls back to valid embedded MAC, and otherwise generates a time-derived address (`wlan_lib.c:3988-4042`). A generated address is not stable device identity. Do not log or hard-code the saved MAC.

Conninfra/WLAN pre-calibration backup is a different, runtime RF-register path: callbacks register in `gen4m/os/linux/hif/axi/axi.c:422-424`; `conninfra/core/conninfra_core.c:560-693` coordinates BT/Wi-Fi calibration and backup; `conninfra/platform/mt6895/mt6895.c:771-878` copies RF CR data out of EMI and later restores it over SPI. It is not an additional named on-disk calibration file in this source. The saved `WIFI` NVRAM file covers static per-device data, not evidence that runtime pre-cal has run or that RF backup is present.

No calibration bytes, MAC value, or live-device reads were used in this review. Source-only limits: buffer format acceptance and the userspace NVRAM delivery path were not validated against a running gen4m stack; the selected `CONFIG_MTK_TC1_FEATURE` value for the final target build still must be pinned from its actual config.
