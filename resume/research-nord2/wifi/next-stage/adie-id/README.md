# Next executable boundary: MT6635 identity, not calibration

Prepared `id.c/.h`: pure injected-I/O TOPSPI CHIP_ID sequencer for the selected MT6893 source04d00c25. No active hook, native adapter, device access, SMC or calibration. At this boundary TOPSPI emits a READ command to analog address02c; it is not a passive MMIO snapshot. Separate explicit authorization and a reviewed outer strap/reset transaction are required before hardware use.

## Executable helper and cleanup

`nai_read_id(ops,ctx,1,result)` requires the common table still APPLIED, fresh exclusive cold-origin ownership, WFSYS/BGF CPUs held, exact strap/clock state established and A-die reset deasserted. It acquires RF SPI semaphore11 through a caller-bounded acquire callback, polls SPI_STA18004000 bit5 clear at most100 reads, snapshots TOP_ADDR18004050, writes read-format0000b000|002c=0000b02c, barriers, writes TOP_WDAT18004054=0 to TRIGGER the read, barriers, polls bit5 clear again at most100 reads, then reads TOP_RDAT18004058 full32. Busy polls delay50us between reads; max99delays per phase, no infinite wait. Success recognizes66358a00/E1,66358a10/E2,66358a11/E3. Unknown ID is completed transport, clean restoration, return1; caller must not select a calibration table by guess.

It restores the saved TOP_ADDR and verifies it, then releases ONLY its own acquired semaphore. NEVER save/restore/replay WD: source says the WD write triggers an operation. TOP_RDAT is observed state, not an original writable register that can be restored. If a trigger write, barrier, guard or posttrigger busy check fails, command completion is uncertain: retain semaphore/outer ownership, return clean0, halt. A failed semaphore acquisition other than known-not-owned1 is also ownership-uncertain. A read-data failure after known completion can cleanly restore address/release while returning error. Callback release0 means the source release write completed with ordering, not a destructive reacquire-to-test.

The command guard must NOT require SPI busy0 while a command is running. Use the existing AP/readability/cold master proof, retained table, strap and reset ownership; busy polling is the helper's own phase-specific predicate. Native adapter not supplied, avoiding accidental reuse of common guard14 whose busy0 test would fail during the command.

ASan/UBSan tests exhaust all28 successful callback positions with transient/permanent faults including writes that mutate before returning error, optout/no-I/O,100poll limits, known/unknown IDs, no duplicate trigger and retained ownership on uncertain completion. Source tests independently pin TOP register offsets/readformat/bit5/semaphore11. BSD ARM64 compile PASS.

## Minimal integration sequence after current diagnostic

Current reviewed common transaction RESTORES its table before returning. Calling this helper after that return is INVALID. Future implementation needs a scoped apply -> inner stage -> reverse restore API or equivalent outer transaction, preserving all40 original snapshots and dirty-halt rules. Keep the current diagnostic separate until its hardware evidence arrives.

1. Fresh original-cold proof and source-order D-die/SPI setup. Snapshot all SYSRAM16KiB before any source SYSRAM write if reproducing full setup. Keep backups private, never log efuse/SYSRAM bytes.
2. Original D-die fields: read opaque AP2CONN_EFUSE_DATA18001818, write18052820; write buildmode3 to18052838 (conninfra/Kbuild:115). Then four retention controls/table. These early writes are NOT evidence of final firmware handoff: connsys_a_die_cfg_mt6893:1123 immediately clears ALL18050000..18053fff before releasing A-die reset. This erases both earlier words in the selected source order. Preserve that behavior for fidelity; do not silently move writes after clear or invent an ABI fix. Whether later firmware expects those words is informational uncertainty until a consumer/source explains it; it does not block the CHIP_ID read.
3. For identity-only substage, no firmware/SYSRAM handoff consumer runs, so the full clear is not needed for the SPI transport itself. Treat omission explicitly as an identity diagnostic, not complete a_die_cfg. The original A-die function performs no SYSRAM-content test before CHIP_ID. Actual board clock selector mt6893.c:271–290 returns26M_EXTCXO or26M_COTMS (never52M); adie26m therefore true in this branch. Do not invent52MHz fallback. Snapshot GPIO DIR5/DOUT5 data and MODE22 before GPIO180 output-high/modeGPIO: source writes10005054/10005154 bit20 and10005460 mask70000->0. Existing probe pinmux overlaps; the same sole owner must restore those exact fields. GPIO155 is volume-down and is not this strap.
4. Snapshot ADIE_CTL18001900, require resetbit0 originally0, set only bit0=1 with barrier/readback. Keep clocks/rails from source common setup; do not toggle efuse/calibration/CPU controls. Run bounded `nai_read_id`. Accepted criterion: known66358a** ID, command_complete1, clean1, strap/reset/table/outer restoration all verified. Unknown clean ID is measurement only. Any uncertain command or restoration keeps ownership and uses existing no-Linux-return/manual-reset halt contract.
5. After known identity, return to source A-die config for exact version-dependent sequence, thermal/efuse validity and AFE calibration; do not assume an ID read substitutes for these steps. These change analog state and require separate snapshot/rollback assessment. Source includes efuse control commands and auto-calibration pulses whose physical effects are not erased merely by writing original register values. This is a real execution prerequisite and risk boundary, not an unknownSMC loop.
