# Private initial local regulatory evaluator

`nre_evaluate(caps, board, out)` consumes provided actual TAG3/PHY metadata and authenticated full-board metadata through the reviewed regulatory-policy types. It evaluates all 39 selected hardware channels against the complete selected Android local DB. It returns source-observed flags, rule identity, frequency/bandwidth, power/CAC metadata, and indices of channels fitting 20 MHz and a conservative passive subset. It sends no command, touches no radio/transport, and never grants TX authority. Actual runtime country, TAG3/PHY contents and firmware quotas remain unknown to this package.

The caller must retain the actual owned capability frame and authenticate the full board before deriving these metadata. These plain structs cannot prove provenance or ownership. The future adapter can copy the same-worker BASIC capability metadata into `nrp_caps` without another query; no boolean, fresh worker, copied receipt or package output admits a native callback. Existing BASIC completion, source normal initialization order and actual regulatory/power prerequisites remain necessary. No native binding or current image is changed here.

This models the initial selected SINGLE_SKU/local-DB branch only. Missing TAG3, missing PHY or zero NSS refuses atomically; absent TAG3 does not imply V2 support. A present TAG3 uses the full four-byte efuse country when valid, otherwise source reset country `00`. Board country never overrides it. Seven exact local keys (`US01`, `US`, `CN`, `NL`, `CZ`, `JP`, `TR`) are searched with all four bytes. An unmatched key, including reset `00`, uses the complete source `default_regdom_ww`, whose label is `99`. The output preserves requested country, efuse/reset origin, exact local match versus world fallback, and table key independently. This broad fallback is a source observation, not universal geographic permission or a regulatory decision by the native system.

All source rules are retained, including Japanese ranges with no matching selected hardware channels. `REG_RULE_LIGHT` sets antenna gain and EIRP to zero; those exact values are reported in mBi/mBm, not replaced with the separate country power table's MAX_TX_POWER value. SOC3 selects HE80, 6 GHz is off and the unoverridden BW160 default is zero, so the world table uses 80 MHz. Country tables may specify other source bandwidths; this evaluator only admits channels fitting 20 MHz. AUTO_BW combines adjacent/overlapping ranges and applies the selected kernel's limiting flags. No 10/5 MHz fallback occurs in `handle_band_custom`.

The selected custom-regulatory function resets current channel flags before applying the non-self-managed kernel rule mapping. Evaluated `flags` reproduce that branch; if no rule fits, original hardware flags plus DISABLED are restored. In particular, broad world rules may clear an evaluated DFS flag. The original hardware DFS marker is therefore retained separately in `hardware_flags`; the initial passive subset conservatively excludes either evaluated or original DFS, as well as indoor-only and disabled/no-20-MHz channels. NO_IR is retained and does not exclude passive reception. This extra hardware-DFS filter is explicitly narrower than the source-evaluated allowed list. PHY and both board 5 GHz switches further restrict the set. No fixed list such as 1/6/11 is substituted for evaluation.

Output is a bounded 39-record result plus index arrays. It is assigned only after complete validation; refusal leaves output unchanged. Callers provide distinct input/output objects. `tx_authorized` and `power_path_resolved` always remain zero. `allowed20` means only that the modeled source rules and supplied band metadata permit that width. It is not approval to activate even passive scanning; power/DFS state, ownership, normal command ordering and a separately reviewed scan/RX implementation are still missing.

The finite power-path audit is in `power-contract.json`. TAG3 presence would select the conditional V2 country-power path; the selected SOC3 initializer supplies neither its file pointer nor nonzero batch size. Missing file load does not prove the source stops: initialized MAX_TX_POWER data and the ignored load result can reach version-zero batching. No other-chip defaults, table, batch size or active runtime bug is inferred. This pure package does not send CID49/CID5d, skip power initialization or claim the path resolved.

`test.py` verifies source-table extraction and ASan/UBSan behavior for every local key, all 65,536 low-country combinations with unmatched upper bytes, full channel counts, band intersections, atomic failures, AUTO_BW and 20 MHz boundaries. `test-kernel-reference.py` extracts the selected kernel function bodies verbatim and compares 131,072 flag combinations plus 27,768 rule/frequency evaluations, with sanitizer failfast. This checks mapping against source rather than mirroring the implementation. Normal ARM64 compilation uses the recorded prior command with only source/output substitutions; it adds no include paths or forced feature define. The recorded static stack use is bounded. Compiler warnings and exact commands are retained, and no full CI or linked/native integration is claimed.

Source pins, extraction anchors and license notices are supplied. This is a private research derivative; promotion requires independent review, normal sibling integration, appropriate licensing review and fresh source/image validation. No frozen package, canonical source, stage gate, NOTES, git, CI, device, UFS, boot speed or audio state was modified.
