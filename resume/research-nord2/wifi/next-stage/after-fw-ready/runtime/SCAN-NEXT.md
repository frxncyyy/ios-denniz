# Next RX routing needed for real scan results

This is a finite source port plan after the current main/capability outcomes. It does not activate scanning or publish iOS Wi-Fi.

1. Keep the same retained pool, firmware and driver owner and extend the worker to service all five **already initialized** RX queues. Selected `soc3_0.c:363–413,693–718` maps software event1→DMA1 RX0; software data0→DMA0 RX0; software data2→DMA0 RX1; TX-done3/4→DMA0 RX2/3. Poll their source-defined DIDX/DDONE and coherent flags, keep independent consumer indices and enforce each exact `nwi.rings[]` descriptor/buffer identity. No global reset or ring allocation is needed. The current native memory allowlist deliberately covers only the event slot; extending it to these exact source queues requires a separate reviewed change.
2. Copy an owned completed buffer before RX rearm. `hal_pdma.c:1554–1690` chooses data-copy versus event-copy by software port, then classifies the actual RXD packet type. Port alone is not enough to decide the payload kind. It handles MSDU reports and RX reports separately before normal RFB queuing. Those handlers and host token ownership must be implemented or explicitly refused; never silently rearm an ownership-changing report.
3. Decode selected CONNAC2X RXD24, not an Ethernet frame at a guessed offset. `nic_rxd_v2.c:220–280` orders optional groups **4,1,2,3,5**; their selected sizes are16,16,8,8,72 bytes (`nic_rx.h:738–778`, SOC3_0 `group5_size` at1172). Group-valid bits come from DW1[15:11]. Header offset comes from DW2[15:14]×2 (`nic_connac2x_rx.h:105–106,133–134,377–384`). Check every group increment and RXD byte count against descriptor length/3840-byte ownership; reject subtraction underflow before computing the MAC payload length. Port the selected sanity/error checks rather than allowing bad-FCS or decrypted/offloaded frames to masquerade as BSS management frames.
4. Source `nic_rx.c:3615–3705` routes software-defined packets by `(RXD upper16 & 0x380f)`: event0x3800 versus frame0x3801. A frame with offload/header-translation flags uses the data path; otherwise it uses management handling. Management dispatch at `nic_rx.c:102–132` sends probe-response subtype5 and beacon subtype8 to `scanProcessBeaconAndProbeResp`; unrelated types need their source handler or a deliberate bounded refusal. This candidate capability dispatcher rejects management frames instead of parsing their bytes as EIDec.
5. Validate 802.11 header length and the fixed12-byte beacon/probe body before walking IEs (`scan.c:3393–3437`). Produce a retained BSS record with binary SSID+explicit length≤32, BSSID6, source channel/frequency, source RCPI/RSSI conversion, beacon interval/capability, age and bounded raw IEs. Each IE needs header2 and length≤remaining. Preserve RSN/WPA IEs; report truncation explicitly so missing security information never implies an open network. Keep scan data in owned managed-memory snapshots; do not retain a pointer into a rearmed DMA buffer or print nearby SSIDs/BSSIDs in generic logs.
6. Before CID3, port normal capability resource accounting, CMD_BASIC_CONFIG2, network-address/BSS setup and selected manufacturing/regulatory initialization. `wlan_lib.c:1333–1407,4049–4107,5290–5345` calls these in order. The full selected NVRAM fragment path is distinct from the228-byte FORCE_CAL NVRAM subset; `wlanLoadManufactureData` sends regulatory domain then full NVRAM fragments. Country/channels/dwell must come from the actual board/source policy, not a hardcoded invented location.
7. Build the source1188-byte CMD_SCAN_REQ_V2 using the layout evidence in the parent directory. Initially use a bounded passive request over validated legal channels. Track its payload scan sequence separately from the command header sequence. Continue servicing all RX queues while waiting for unsolicited SCAN_DONE0x0d; source `scan_fsm.c:249–465,865–983`, `wsys_cmd_handler_fw.h:1129–1159,1687–1721`. SCAN_DONE contains completion/channel statistics, not BSS records. Deliver a real scan snapshot only from received beacon/probe frames and the matching scan completion/deadline.

The future hardware-neutral API can expose asynchronous scan snapshots once those facts exist. A BSD ifnet remains link-down until actual association/key installation and a data path work. iOS Settings additionally needs its real Wi-Fi control bridge; a wlan ADT node alone must not advertise availability. These boundaries follow the existing exact Topaz reference report, whose public checkout does not contain that bridge.
