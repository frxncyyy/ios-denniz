# Private bounded runtime capability candidate

This separate revision leaves the reviewed pure capability and main-firmware packages unchanged. It is a source candidate, not an activated radio or interface. Execution requires the actual current main FW_READY outcome.

`dispatcher.c/h` consumes the reviewed real initializer and firmware-state objects: initialized phase5, exact low-pool layout/accepted region18 receipt, driver ownership, main events3/finish2, completed span mask0x7f/next7, successful coex/CID41 and FW_READY receipt. It checks live SW_SYNC0 bits0/1 before one CID8a submission. The native adapter additionally pins the exact global object identities and current worker thread; no Boolean callback can grant readiness. The old main source pipeline is never rerun.

The candidate pins the current pool binder's explicit `ml_io_map_unmappable(..., VM_WIMG_IO)` mapping, not historical heuristic `ml_io_map` behavior. It reuses exactly that retained VA and introduces no DRAM alias or fake cache-sync callback. The three parent binding includes are snapshotted under `baseline/` for reproducible private compilation while parent integration continues; only their include paths change in the proposed copy.

The command and event buffers live in retained state. Before overwrite, the current TX slot must be free; command/descriptor visibility precedes CIDX publication. Completion requires DIDX and DDONE, exact source-defined TX descriptor fields, and owned single-segment RX pointers/length. Global source coherent bits20/21 are checked throughout and before every RX rearm. Any uncertain operation shares initializer/transport/native halt and reaches the reviewed manual-reset panic policy. There is no retry, global reset, new MPU call, firmware replay or DMA teardown.

One monotonic3-second deadline includes TX and RX work and is never reset by unsolicited traffic;3000 polls and16 events are independent finite caps. Time regression/overflow and callback errors halt. The actual native clock is `clock_get_uptime`→`absolutetime_to_nanoseconds`→microseconds, not a sum of requested sleeps.

The RX adapter verifies the actual selected software packet discriminator: RXD upper16 masked0x380f must equal0x3800 (`nic_rx.h:1128`; `nic_connac2x_rx.h:80–82`; source V2 query `wlan_lib.c:6860–6897`). It then checks normal WIFI_EVENT12 at RXD24. The selected Linux first-capability wait matches EIDec only (`wlan_lib.c:6860–6897`), so this revision does likewise after actual TX completion. It records requested/reported sequence and echo mismatch without requiring an echo. The unchanged reviewed `ncp_parse` receives the captured event sequence for structural parsing; this is not claimed as request-sequence correlation. This source-backed first-query rule supersedes the speculative strict-echo paragraph in the parent `DISPATCHER.md` design. It cannot be generalized to later concurrent commands. ASCII DEBUG_MSG0x27 uses the source12-byte body header, type3 and size≤1200/owned extent (`nic_cmd_event.h:2471–2480`, `wlan_lib.h:583–598`, `nic_cmd_event.c:4366–4432`); only metadata is retained, no payload printing or QA action. Sleepy0x07 can hand ownership back to firmware (`nic_cmd_event.c:3783–3800`), so it is not safe to skip. Unknown, state-changing, assert, malformed or management-frame messages capture metadata and halt **without RX rearm**. This is a deliberately small supported dispatcher, not a claim all unsolicited events are harmless. No real normal event has yet been captured.

`capability_bind.inc` is a private proposed adapter/hook. A distinct default-off `nord2wificap=1` plus actual successful `nord2wifimain` state schedules one dedicated kernel worker **after** `nwfn_after_pool`; nothing waits on the touch input thread. The selected persistent caller does only captured logging/return after this hook. Worker creation failure performs no radio callback. The worker owns all new callbacks, static buffers and the exact retained objects, and rejects other threads. Success retains and parks that worker; it does not claim continuous RX service, implement a generic request queue, publish an interface/MAC/carrier or sleep the active DMA engine. Subsequent normal work requires an explicit reviewed queue/consumer extension. Old callbacks are not repurposed or invoked after an error.

ASan/UBSan tests cover all128 successful-path callback fault positions, committed failing writes, debug events before EID match and both echoed/non-echoed sequence cases, wrong-thread and prior-receipt refusal, native worker deferral/creation failure, shared halt/panic, event budget/ring wrap, clock rollback/deadline jump, descriptor flags/extensions, malformed TLVs, unsupported ownership/assert events and coherent faults even after a valid event copy. Native synthetic DMA is explicitly a host model, not firmware evidence. Normal CI-derived ARM64 compilation covers the actual private whole `sweet_touch` copy plus the dispatcher TU, without forcing NORD2. No image or CI/device action was performed.

See `SCAN-NEXT.md` for exact five-queue management/BSS routing and manufacturing/regulatory prerequisites. Capability decode success alone is not normal-operation readiness, MAC publication or networking.
