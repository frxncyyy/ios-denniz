# Private normal-init command primitives

This new package supplies useful pure bytes and bounded planning while actual FW_READY/capability data remain pending. It leaves frozen packages unchanged. It performs no MMIO, DMA, command submission, calibration, policy selection or interface publication.

`nni_basic` builds the exact 76-byte normal CID2 set frame: MAC32 plus normal WIFI_CMD32 plus the source 12-byte CMD_BASIC_CONFIG. Native80211, checksum-offload and segmentation fields remain zero; assert path and level are explicit source-enum inputs, with no guessed runtime flag. This is a deliberate no-checksum-offload configuration suitable only when the host does not claim checksum acceleration. The selected AXI default is path WIFI0/level ERROR0 (`debug.h:230–236,562–567`; `wlan_lib.c:7931–7936`), but the helper does not silently select it. All source-reserved fields and PQ/S2D metadata remain zero; packet type is the actual macro `0xa0`, setQuery1 and CID2. Source command header length excludes MAC32. Source `wlanUpdateBasicConfig` sets `fgNeedResp=FALSE`: TXDIDX/DDONE completion is not a firmware command-result ACK, and a future adapter must not wait for an invented EID1.

`nni_nvram_plan` follows the selected manufacturing fragment algorithm: TLV headers are three bytes at offset256, each command includes one complete tag, and the first command additionally carries bytes0..255. The zero ID/zero length terminator ends the stream. Each outgoing CID48 payload is **1500 bytes**, zero-padded; the full wire frame is1564 bytes. The saved authenticated 6146-byte WIFI file produces12 fragments of 262,113,145,824,824,902,902,77,89,59,67,33 bytes, terminates at4297, and ignores1846 bytes after the three-byte terminator as the selected source does. It does not blindly send all6146 bytes and is separate from FORCE_CAL's228-byte subset. The planner adds finite32-tag, source-extent and1500-byte bounds that the original loop/memcpy lacks. It refuses malformed/truncated/oversized input without changing output. `nni_nvram_fragment` revalidates structural plan identity before copying and zero padding; it is not a cryptographic verifier and cannot detect payload mutation that leaves structure unchanged. The future native owner must retain the exact SHA-pinned board file immutably, not trust a caller boolean. Existing `/chosen/nord2-wifi-calibration` contains the full file; `nfa_xnu_prepare` already validates it for FORCE_CAL. Future manufacturing binding must retain/recheck that same full source and its lifetime, rather than rebuilding it from the subset.

`nni_address_select` implements valid host/NVRAM MAC precedence over a real decoded capability address, refusing zero/multicast values and requiring actual capability decode/presence/validity for fallback. It deliberately omits the source time-derived random fallback. It does not invent/publish a MAC, generate a P2P derivative, or claim a capability struct is a hardware authority. The board prefix is a pure input; callers must establish its provenance. Neither tests nor diagnostics print board bytes, country, MAC, SSIDs or calibration payloads.

Source sequence is important: actual normal NIC capability/resource update precedes BASIC_CONFIG; network-address selection/application follows it; post-ready manufacture sends domain/channel policy before CID48 fragments. Source methods often queue commands asynchronously and their immediate returns are not firmware acceptance receipts. These helpers intentionally do not supply a fake normal-ready state machine: the existing retained native transport still needs a reviewed TX-only completion path for no-response commands, a real bounded request/unsolicited-event worker, and exact normal command-resource accounting from received capability data. The reviewed first-query worker parks after capability; it is not yet that queue. No CID3 scan is built or enabled here.

The exact outstanding regulatory work is finite: selected config enables SINGLE_SKU and local DB (`include/config.h:1331–1333`). `rlmDomainSendCmd` calls domain setup (and passive-scan setup for non-SINGLE_SKU); V2 domain setup constructs enabled channel lists from the actual Linux wiphy/regulatory state. A native port must establish the real board country/domain, source regulatory rules and capability-supported bands/channel flags before emitting equivalent domain commands. Passing an arbitrary country string or assuming every hardware channel is legal is not a substitute. Current actual first capability resource totals, MAC validity and supported PHY limits have not been received; therefore resource configuration, final address choice and legal scan channel/dwell policy remain blocked on real data plus that source policy port. Pure byte construction is independently testable now.

ASan/UBSan host tests validate all256 BASIC_CONFIG sequences, exact source fragment offsets/lengths and padding against SHA-pinned saved WIFI,4300 truncated file extents, oversized/too-many tags, altered structural plans, output atomicity and address-source precedence/refusal. Tests use synthetic MACs and never print actual bytes. Source-extracted static assertions establish BASIC_CONFIG size12/offsets and NVRAM_FRAGMENT size1500. Parser/builders compile with normal CI-derived XNU ARM64 board flags, without forced NORD2. These are source/host results, not firmware acceptance or scan/networking evidence.
