# Deferred normal-event dispatcher

This is a design boundary, not an executable owner or a readiness callback. It depends on actual FW_READY and transfer of the retained driver/WFDMA lifetime to one dedicated radio worker. The input thread must not wait for a3-second query or service ongoing RX. No IRQ output should be enabled until an actual handler owns it.

1. Preserve the exact pool/ROM/driver owner, current TX/RX indices and descriptor/buffer visibility contract. Submit only one query, with a unique owned sequence, and reclaim both TX DIDX/DDONE and the matching event before reusing its command slot. No global reset, ring reinitialization, firmware replay or new MPU call.
2. Poll/consume owned event descriptors under one absolute deadline and a finite event budget. Before parsing, require DDONE/LastSec0, low32 pointer match, bounded descriptor length and source coherent-fault checks. Copy the event into retained storage before rearm. Read normal WIFI_EVENT fields at RXD24; its body starts after12 bytes. Separate generic descriptor mechanics from message matching, rather than calling an INIT-result validator.
3. A matching EIDec/sequence goes to `ncp_parse`. Unrelated known events get their own bounded handler or captured metadata queue. Unknown events may be copied as bounded metadata and skipped only under an explicit policy; count/budget them so firmware noise cannot extend the deadline. A stale matching-EID/wrong-sequence event is not completion. Never silently drop an event that transfers host-memory ownership or signals firmware failure. Unsupported ownership-changing events retain/halt; they are not safe unsolicited traffic merely because the capability parser ignores them.
4. RX rearm/publish is permitted only while the exact worker still owns the slot and retained mapping. Any uncertain publish, timeout, coherent fault or malformed matching response shares the native halt latch and follows the reviewed manual-reset terminal policy. Never retry or sleep the active DMA engine after uncertainty.
5. Capability resource information updates normal command accounting before additional operations. A source-backed normal dispatcher and continuous management/data RX service are prerequisites for scan. Before leaving the initial query stage, record actual descriptor/MAC/event counts and TLV versions; synthetic host fixtures cannot establish firmware event production or ongoing asynchronous obligations.

The selected driver waits for capability with a3-second deadline and skips unrelated EIDs (`wlan_lib.c:6848–6897`). It does not provide this smaller native worker or its finite queue policy. Those are implementation work after the current FW_READY outcome, not missing pure packet definitions.
