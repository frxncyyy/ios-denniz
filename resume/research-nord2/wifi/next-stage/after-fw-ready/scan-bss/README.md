# Private selected scan result primitives

This package implements a pure copied-buffer decoder and bounded scan snapshot state. It does not send CID3, map RAM, change a ring, rearm a descriptor, start a worker, publish an interface or establish radio/regulatory readiness. The reviewed capability runtime package remains unchanged. Synthetic tests are not received firmware evidence.

`nsb_decode` handles the selected CONNAC2X RXD24 software-frame discriminator `upper16 & 0x380f == 0x3801`, optional groups in exact order 4/1/2/3/5 with sizes 16/16/8/8/72, and the two-byte-unit header offset. RXD byte count must fit the actual copied descriptor extent; every group and the 24-byte header plus 12-byte fixed beacon/probe body must fit before accessing them. It supports only unprotected, unfragmented, untranslated beacon subtype8 and probe-response subtype5 with a normal 24-byte 802.11 header. Source FCS/ICV/cipher/length/MIC errors, deaggregation/translation/length failures, fragment and offload fields are refused. This deliberately narrower subset does not port Linux reorder/decrypt/data/report handlers. The eventual caller must establish DIDX/DDONE, exact descriptor/buffer ownership, memory visibility and coherent status before this pure API; successful parsing cannot authorize RX rearm.

The output owns its binary SSID, BSSID/transmitter and up to 512 raw IE bytes. All IEs are structurally walked through the actual RXD byte count, including beyond the retained prefix. Malformed or duplicate SSID/DS/HT fields are refused; zero-filled and zero-length SSIDs remain explicitly hidden, with a separate SSID-present bit. Source channel preference DS then HT then hardware is retained, with mismatch metadata. Hardware channel and raw group3 receive vector are captured without inventing frequency, RCPI or RSSI decoding. RSN/WPA presence and the privacy capability bit are metadata only: the code never labels a network open/secure, decodes keys or assumes absent/truncated IEs establish security policy. Raw IE truncation is explicit; a prefix may end within an IE and must never be treated as a complete security description. Every decoder writes its output only after complete validation. No nearby SSIDs/BSSIDs or payloads are logged.

`nsb_decode_done` decodes the exact selected 476-byte `EVENT_SCAN_DONE` body, including scan payload sequence, firmware state/version, channel statistics and little-endian idle/time fields. Source-extracted ARM64 static assertions establish every consumed offset. It requires the full selected layout, captures version and does not claim support for older shorter events. `nsb_complete_event` additionally classifies a copied RXD24 plus normal WIFI_EVENT12, type `0xe000`, EID `0x0d`; command-header event sequence and embedded length fields are captured separately. Like the selected normal-query path it imposes no invented embedded-length equality. Descriptor extent still bounds every access. The body-only API is explicitly for an already classified event.

`nsb_begin` records the scan payload sequence and a finite monotonic deadline of an **externally issued** request; it is not a send operation or an authorization receipt. State must be zero initialized and is one use. `nsb_add` keeps at most 16 independently owned results, updates matching BSSID plus binary SSID, records capacity loss as partial and never invents a hidden-name merge. `nsb_complete` accepts only the matching scan payload sequence; mismatches leave the scan active. Completion state other than source `FW_SCAN_STATE_SCAN_DONE=7`, deadline expiry or time regression mark the snapshot partial. Completion itself never creates BSS entries: an empty completed scan remains empty. Structurally malformed input returns an error and cannot create a result; the future worker must choose its source-backed drop versus fail-stop policy before touching DMA. This is a bounded observation container rather than Linux's full BSS cache, ranking, aging or association logic.

ASan/UBSan tests exercise 256 selected group/offset/subtype layouts and 36,352 truncated extents, every refused source error bit, output atomicity, binary SSIDs, security IE retention/truncation, malformed IE tails beyond the snapshot boundary, bounded capacity, timestamp/deadline/sequence handling, normal EID discrimination and completion-versus-results separation. Both source-extracted layout and parser compile for freestanding ARM64; parser also compiles with normal CI-derived XNU board flags, without a forced NORD2 macro. Run `python3 test.py` for host-only validation.

Before any future runtime use, unsatisfied prerequisites remain: actual FW_READY and capability results; normal resource/basic/BSS/network-address configuration; full manufacturing NVRAM and real regulatory domain/channel policy; source queue ownership and native allowlists for all five already initialized RX queues; explicit RX/MSDU-report/data/ownership-changing event handling; a retained request queue instead of the capability worker's parked terminal state. No scan builder is supplied while those policy inputs are absent. Future integration should keep EID0d on the event path, route validated beacon/probe software frames from actual source RX queues into this parser, copy results before any safe rearm, and finish the request only after the matching scan completion or deadline. An ifnet/iOS Wi-Fi bridge, real association/key installation and Ethernet data path remain separate work.
