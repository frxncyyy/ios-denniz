# Private runtime capability rebase after TX descriptor changes

This directory rebases the previously reviewed, still-default-off `nord2wificap=1` capability query candidate onto the source state at commit `45a03c3f3aeb6c94f92bf308a3aefb20aee6675c`. It does not enable a runtime path. Main firmware `FW_READY` has not been observed, and neither this candidate nor its synthetic tests claim radio, scan, interface, or networking readiness.

`baseline/` snapshots the canonical main, WFDMA, transport, initializer, firmware, pool, and failure-drain sources and headers used by this private build. The TX descriptor fields in `struct nwt_state` are now present in the dispatcher's `nwi_state` dependency. The parent main binder snapshot includes PRESPAN, PREORDER, TXDESC and the retained 30-second failure drain. Its only private textual normalization is the include of `baseline/failure_drain.inc`; `check-pins.py` verifies exact equivalence after that normalization. The original frozen `runtime/` package is untouched.

The dispatcher, capability parser, and one-use worker behavior remain unchanged: actual retained main/pool/ROM receipts and FW_READY are required; the input thread schedules a dedicated worker only with `nord2wificap=1`; one bounded CID8a/EIDec query runs through the retained DMA owner; failures share halt and manual-reset panic; success parks the worker without exposing a network interface. There is no new readiness boolean or capability bypass.

`python3 test.py` runs host ASan/UBSan dispatcher and adapter tests plus a **separate-translation-unit** comparison of 21 layout fields: one TU includes private snapshots, the other includes current canonical headers. This matters because the prior private initializer header lacked the newly appended TX descriptor fields. The dispatcher and a private whole `sweet_touch` include candidate also compiled with the available CI-derived ARM64 flags. The whole-TU candidate is derived from the earlier private source copy with current snapshotted binders, not a production integration build. Its extra include path and historical CI header buildtree are recorded in `whole-arm64-command.json`; the parent must repeat an actual production compile after any integration.

`check-pins.py` checks the commit and hashes against live canonical sources. Its pins are a source identity guard, not hardware evidence. If current canonical sources change, regenerate and review a new private rebase; do not silently update this manifest.
