# Private one-command BASIC_CONFIG continuation

This candidate adds `nord2wifibasic=1` after the actual retained capability
receipt on the same dedicated worker, before parking. Absent or non1 arguments
perform no new metadata decoding, logging, ownership admission or backend call.
No canonical source, generated buildtree, git, CI, image, gate or device was changed.

Actual successful CAP first/full receipts and their exact limits are recorded in
receipt-review.json. Actual firmware quotas, PHY and tag3 contents were not
persisted in those logs; host fixtures use explicitly SYNTHETIC values. The next
bounded image can decode that still-owned frame and attempt the source CID2 in
one milestone. No actual BASIC transaction or network activity has occurred.

The source order and helper provenance are pinned in source-evidence.json.
Four new pure TUs and one native binder are proposed, with only two existing
binders changed. runtime.patch also includes the exact generated sweet_touch
lease hook, four bsd/conf/files entries, and generator additions. Parent must
review/promote, regenerate, compile normal sibling context, run CI and review
the resulting linked artifact before preparing a separately authorized image.
All build/image/authorization gates remain false here.

BASIC is exactly76B, CID2 set/noresponse, current sequence (normally5), source
assert path0/level0, native/checksum/segment/reserved0. There is NO MAC field.
This package explicitly supersedes the inherited normal-resources README's
suggestion to gate CID2 on address availability. Board MAC provenance is
preparatory for later address/BSS work; it is neither reread nor applied here.
No unused address, NVRAM, domain or scan builders are promoted.

Pure preparation revalidates the same completed CAP frame with the canonical
parser, derives a version80000001 resource plan with nonzero actual PSE command
quota, and captures tag3/PHY metadata. Unknown TLVs remain supported. Missing
optional tag3 is reported as absent and cannot enable regulatory operations.
Metadata decoding failure reports valid0 and cannot grant such operations;
it does not change the source resource-only prerequisite for BASIC. Failure of
CAP/resource/BASIC preparation skips before ANY backend callback and parks with
completed4. Reasons1=CAP/shared receipt,2=reparse,3=resource,4=BASIC formatting.

Native authority is the exact static object, same cap/init/firmware pointers,
actual current worker, active/nonparked/nonhalt lifetime, CAP receipt and the
one-command phase. The new macro defaults false in every other context. Only
the late ENA29 allowance is widened from completed3 to completed4 while that
lease is true. GIC, AP/WF ownership, actual STA29 and all existing guards remain.
No generic completed>=4 allowance exists; completed5 closes the lease before
any further backend callback. Shared native/init/transport/capability ABI sizes
remain7472/3040/1176/5152.

TX uses the existing owned command buffer/ring. A one-way1PSE/0PLE debit occurs
immediately before the one CIDX callback attempt. Credits are never refunded,
even on failure, publication uncertainty or DDONE. Source AXI normally releases
its software debit after publication; retaining one and parking is deliberately
narrower. publications counts callback attempts after ownership/time checks;
an error never proves hardware publication. Success requires DIDX next and
DDONE with either exact consumed control80000000 or software length-preserving
c04c0000. TX completion is NOT a firmware ACK. firmware_ack=0 is intentional.

The worker checks real3s monotonic deadline, at most3000 polls and16 existing
ASCII debug events. Pending source-compatible debug events may be captured and
rearmed; it never waits for a nonexistent CID2 response. Outer380f/3800,
innerE000, EID27, ASCII type3 and bounded payload length remain strict. Declared
lengths/sequence are captured metadata, not invented matching requirements.
Only last debug RXD24+event12 header and bounded type/id/length/index are logged;
no body/MAC bytes. Unknown or malformed pending RX halts without rearm.

Any run failure sets all common halt flags before captured-only reporting,
then uses the existing actual fixed30s scheduler drain and terminal panic.
No retry, teardown, W1C, firmware-credit invention or callback follows completed5
or a failed callback. A skipped attempt prints no ARM/TX and zero callbacks,
publications/debit. Successful logs print CAP report, BASIC rows, BASIC WORKER,
then original CAP WORKER. Both parking rows describe the same retained worker.
No interface/carrier/scan/association/network readiness is claimed.

Run `python3 test.py`. ASan/UBSan fixtures use the REAL proposed nwfn_owner and
macro lease, with synthetic register/DMA hardware only. They cover defaultoff,
exact worker/object ownership, clone/wrongthread/replay refusal, actual STA29,
resource skip with zero callbacks, no MAC prerequisite, one76B publication,
DDONE/consumed control, debit, completed5/park, commonhalt actual30s drain, and
all67 callback failure positions with no later callback/retry/refund. Independent
review adds bounded debug probes. These are host checks, not hardware success.
