Private completed-scan adapter age revision; old frozen package remains unchanged. niwaa_age_plan validates a completed state7 immutable nsb_scan, explicit captured_us and reference_us, and all retained host observation timestamps before output mutation. niwaa_snapshot_prepare then supplies those ages to the original snapshot adapter. No hook/service/native integration. Caller must serialize ownership and retain output without relocation as required by original cursor API.

Actual time provenance is host monotonic uptime, not firmwareTSF/beacon timestamp: wifi_capability_bind.inc ncd_native_now reads clock_get_uptime→absolutetime_to_nanoseconds→ns/1000; ncr_pump obtains this clock and passes now through classify→nsb_add→nsb_decode, which stores observed_us. Duplicate BSS replacement refreshes that timestamp. Source does not recover original air-arrival time; this measures age since host processing. Same-clock capture/reference is an owner obligation that pure numbers cannot authenticate. Captured_us must be at/after scan.last; reference_us must be at/after capture; records must lie within scan.started..last.

Apple AGE milliseconds is proven by result-conversion-audit. Conversion floors(reference_us-observed_us)/1000; submillisecond age is0. There is deliberately no saturation: refuse future timestamps, bad ordering, incomplete scans and ages above INT32_MAX milliseconds because framework boxes raw age as signed32CFNumber. All refusal leaves age/output unchanged. uint64 subtraction occurs only after ordering validation. Ages are fixed at the explicitly supplied reference instant; future realGET lifetime must choose/refresh reference deliberately, not silently pretend snapshot time is current.

Rates remain unknown. No production rate table is included; integration test uses synthetic123 to prove plumbing only, and missingmap refuses populated rows. No BSS/SSID/MAC/calibration data logged.
