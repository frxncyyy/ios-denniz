# Concrete private iOS scan service candidate

One integration candidate, default off via sole `nord2wifiios=1`. Root owns canonical assembly, ADT node, build/CI and hardware approval. This is supported scan/control plumbing, not association, authentication, encryption, host data TX/RX, IP connectivity or carrier readiness.

## Actual publication and backend connection

`Registry.cpp` implements new IOService-derived `IO80211Controller`, `IO80211Interface` and its `IO80211SkywalkInterface` subclass. These use ordinary IOService/IOUserClient methods, not proprietary class layouts/vtables. The controller is provider-parent of the actual interface. Backend `nord2_wifi_ios_backend_ready` first checks the real retained scan-service info, then submits an in-kernel catalogue personality for the explicit software ADT `wlan` IOPlatformDevice with compatible `nord2,mt6893-wifi`. No MMIO address comes from this node. XNU IOCatalogue.cpp651 treats personalities without bundle keys as in-kernel; IOService.cpp3998 allocates the actual registered metaclass.

Start attaches a real BSD `enN` ifnet (Ethernet family, WiFi subfamily), using authenticated actual board MAC from native `nord2_wifi_scan_info`, addrlen6/header14/MTU1500 and verified link-layer address. Unit collisions try only0..31. No link-on event or carrier is signaled; RUNNING/UP are initially clear and packet output frees/refuses ENETDOWN. Protocol/data paths remain unsupported. `SIOCGIFMEDIA` exact64-bit ABI44B/0xc02c6938 returns IEEE80211|AUTO with AVALID and without ACTIVE. A requested one-entry list uses bounded copyout; unknown commands fail, administrative SIOCSIFFLAGS changes no radio/link state.

Actual interface alone receives IOInterfaceName, BSD Name, unit/type and string IO80211InterfaceRole=Infrastructure. This satisfies the recovered wifid property-match, interface-name and actual SIOCGIFMEDIA type predicate. The controller's real metaclass satisfies generic IOServiceMatching(IO80211Controller). Some legacy framework GetIfList paths additionally whitelist Apple hardware class strings; this candidate does not forge Broadcom/ACI hardware identity. Whole Settings startup still requires an approved run and may reveal additional initial queries. Numeric bounded unsupported-request logs are intended to distinguish those, not claim complete wifid compatibility in advance.

## Actual IOUserClient and scan/event flow

`LifecycleShell.cpp` retains actual owning task, manager-access entitlement, type0 open, IOLock, mappings and owned async send reference. Both small/large carrier paths are bounded; OOL input requires exact extent, prepare(DirectionOut), read and complete, with balanced failures. The real interface name must match. Selector1/5 report implemented control/pipe shape support; selector3 allocates real4096B descriptors, maps1 read-only data and2 state, selector2 adopts exactly8 references, selector4 closes the generation and cancels delivery outside the gate. Close/death revoke admission before cancel and release. Pending native work retains the client and snapshot until callback retirement. No gate is held across radio scan wait.

SET10 admits only the precisely zero-initialized source-built null-dictionary5456B discovery profile (version1/BSS3/default-mode1/PHY1, no directed SSID/BSSID/options/channel override). Root explicitly chose to fulfill this unrestricted discovery request with a passive all-allowed native scan. Mode1 is called default; it is not asserted to be a recovered passive enum. Unsupported advanced/directed options fail. Native queue owns actual source plan/regulatory channels, serialized owner/credits, deadlines and cancellation; client thread never performs radio MMIO. Native completion callback runs outside queue lock. It acquires client gate, verifies request serial AND mapping epoch, converts immutable retained real scan with proven millisecond ages and the reviewed12-entry driver compatibility rate map, installs complete cache before publishing event10, then releases the native ticket (deferred until callback returns) and client reference. Queued cancellation does not call back inline; in-flight radio work finishes bounded without reset/replay.

Complete empty returns exact EOF0xe0820446. Populated GET11 returns actual bounded1164B rows then EOF. Partial/failure never becomes completed empty. GET12 emits a truthful13-byte zero security bitmap from an empty installed inventory. GET19 returns powered1 only while actual retained native scan-service info is valid, distinct from carrier/association. GET43 returns this driver's own bounded identity; invalid interface/value cannot be overridden. Other valid SET/GET IDs return Unsupported with bounded numeric diagnostics, no payloads.

Event record is consumer-compatible52B/kind87/event10/primary4. Gate serializes one producer, acquire-loads untrusted consumer, validates bounds/space, writes immutable record/padding, release-publishes producer, then sends through the current retained reference. Full ring fails before publication and invalidates transaction availability (NoResources, never fake EOF). Notification failure after publication leaves the already visible real cache/event intact and logs notified0; it never retracts or fabricates a record, replays radio work or claims consumption. Close can't free a mapping/reference during a send because both run under the same gate. Old mapped descriptors keep their own refs and are never reused. Request serial plus independent mapping epoch prevents late old-session events even at counter limits.
