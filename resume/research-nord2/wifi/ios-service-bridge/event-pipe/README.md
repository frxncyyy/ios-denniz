Private mapped-event pipe contract

This package preserves all three service milestones and reviewed passive-scan/v2. It reuses their exact same-IPSW framework/wifid identities and shell disassembly; no REA engine/decompilation/runtime evidence, live mapping, service registration, device action or kernel activation. `source-excerpt.txt` pins the actual consumer/halt instructions; XNU source anchors below identify generic mechanisms rather than an unavailable Apple IO80211 producer implementation.

Exact consumer observations

Apple80211EventMonitoringInit2 invokes selector5 (one-byte useIOUCEventPipe), selector3, maps type1 data(options0x1001) and type2 state(options1), then selector2 async8 references (0x1d3ed2110,230c,2414,2550). Callback0x1d3ee5814 requires connection/data/state then reads producer32@state+4 and consumer32@+0. Equal indices mean empty. It snapshots consumer, executes DMB ISH, checks mapped size, pointer alignment and first word, copies48-byte header then checks consumer/first word stayed stable (58b8–5a44).

Kind80 is a **four-byte padding step**, not a jump to index0:5974–5998 advances(consumer+4)%capacity using exclusive load/store CAS. A tail with fewer than48 bytes uses the same step regardless of kind. A compatible producer must leave four-byte-readable aligned tail words and must not leave an incomplete event header there. Event kind87 is required at5a48–50; its primaryLE16@24 and secondaryLE16@26 determine total48+primary+secondary. Header must fit contiguously; primary data may wrap to buffer0. Interface16@32 is copied, event32@28 becomes kern_event_msg.event_code. Header bytes4..23 are not consumed by this callback, but their original producer meaning is unproved.

Primary copy is capped4080 bytes (5ad4–5b94); secondary bytes are **skipped**, not appended to the event payload, while they still contribute to cursor advancement. It calls the common event handler then rechecks consumer, first word and both lengths (5bdc–5c24). Only then it computes next modulo capacity and requires4-byte alignment before CAS (5c28–5c50). This means a callback may already have run before a late mutation is detected; the checks are not a cryptographic snapshot or duplicate-delivery guarantee. Publisher must keep published bytes immutable until consumer advancement. Do not overwrite/drop the oldest published event by rewriting consumer.

Bounded pure implementation

`niwe_peek` and `niwe_copy_primary` operate only on an immutable copied ring and separately copied index snapshot. They do not read live shared memory, execute barriers/CAS or own a callback. Their additional safety subset requires capacity52..1MiB/aligned, indices strictly below capacity/aligned, the entire event extent within the published distance, total<capacity/aligned and primary<=4080. These checks are deliberately stricter than the disassembled consumer; no claim is made that other Apple queue capacities/truncation behavior are invalid. Outputs are atomic on refusal. Copy recalculates offsets from the immutable snapshot and validates supplied metadata; caller supplies disjoint output. It cannot authenticate a concurrently changing shared ring or task ownership.

`niwe_scan_done` formats a52-byte event87/event10/primary4/secondary0 record from caller-provided interface and actual status. It zeroes uninterpreted header4..23 as a consumer-compatible offline subset, not a recovered original producer format/monotonic identifier. It never manufactures backend completion, publishes a ring index or sends a notification. Existing copied event10 classifier independently agrees with this52-byte consumed shape.

Full-ring policy, proved limits and proposed plan

The actual IO80211 kernel producer is not present in the public Topaz tree or selected generic XNU source. Consumer equality proves that a producer cannot use consumer==producer to represent a full ring without additional unavailable state. `niwe_plan` therefore implements an explicit private SPSC policy: leave4 bytes unused, reserve all necessary tail padding plus event before any write, refuse insufficient room atomically, and never advance consumer. When fewer than48 bytes remain, the proposed writer would fill that tail with kind80 four-byte words, then put the contiguous header at0; payload may wrap. Planning is pure and uncalled. This is a compatible conservative policy derived from the consumer, NOT a recovered Apple producer/full-ring/drop policy. Failure must leave an actual scan completion pending or fail the transaction explicitly; never report completed empty results because the event queue was full.

The generic XNU `iokit/Kernel/IODataQueue.cpp:176–254` separately demonstrates acquire head / relaxed producer, data-before-release publication, strict head separation and a sequential fence plus head recheck before empty-to-nonempty notification. Its entry-size header and wrap behavior differ from this pipe, so IODataQueue is **not** a drop-in format. Its ordering pattern is useful implementation precedent only. Future native event publisher needs actual IOMemoryDescriptor attributes, shared32-bit atomic visibility and single publisher serialization proven in its own owning TU. Prefer release publication after all immutable record bytes, paired with the consumer's DMB; notification must occur after publication. An empty-to-nonempty-only wake policy still needs the equivalent lost-wakeup race proof; no notification implementation is supplied.

Cancellation and native lifetime boundary

Actual Apple80211EventMonitoringHalt at0x1d3ed1f24–58 destroys its IONotificationPort, calls selector4, then clears data/state/size pointers. It does not prove a kernel publisher canceled, an in-flight dispatch callback drained, memory unmapped, or backend RF work stopped. A real selector4/clientClose/clientDied path must first close admission under its owner gate, invalidate the session generation, detach the async reference, cancel queued publication/backend work and wait for actual in-flight publisher/callback acknowledgments before freeing mappings. Do not wait while holding a gate needed by that worker; use an explicit drain state. An already published event may remain in retained mappings, but no new record may publish after the closed generation. Do not recycle mappings for a new session until old references are quiescent.

XNU `IOUserClient.cpp:1851–1865` calls overridden clientClose from clientDied using closed CAS; default clientClose is Unsupported, so it is not an automatic queue teardown. `releaseAsyncReference64:2108–2118` releases the owned send right; it must happen exactly once after no sender can use it. `_sendAsyncResult64:2168+` copies refs into a Mach message and bounds argument count; a null port returns success without delivery. Therefore successful sendAsyncResult64 is not backend completion or proof that wifid consumed anything. Dead/full notification-port errors must not trigger radio reset/replay or premature mapping release. The future shell needs its own real retained owning-task/session state and IOKit scheduling review, not a boolean passed to these pure helpers.
