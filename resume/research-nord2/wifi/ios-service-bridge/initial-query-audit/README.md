Concrete reusable backend boundary

`cache_cursor.c/h` supplies a bounded one-generation pure cursor over **already completed, immutable, encoded** result records. Phases NEW→WAITING→READY or CANCELLED. Before actual completion, take refuses; generation mismatch/reentry/refusal never advances. Completion validates count<=64, exact count*1164 extent and each frozen version1 bounded record; native must retain original scan-completion provenance and immutable storage. Each successful take copies one row then advances, exhausted READY returns0, cancelled refuses. No ACK/event/ready bit is generated. The64-record bound is a deliberate native policy, not a discovered Apple cache capacity; overflow must refuse/truncate explicitly in a separately reviewed real backend, never silently fabricate a full list. Native must serialize/retain the snapshot, supply disjoint output and preserve memory lifetime; parsing again cannot authenticate concurrent payload mutation.

For an eventual actual IOUserClient:

1. An authenticated owning-task/session request10 is fully decoded against implemented scan options and actual MTK normal-init/regulatory/channel receipts. Begin one backend request generation; return unsupported/not-ready for missing prerequisites, not an empty successful scan.
2. The radio worker receives real management BSS observations and actual SCAN_DONE.
