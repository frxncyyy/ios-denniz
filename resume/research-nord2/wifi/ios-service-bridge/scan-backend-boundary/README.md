Concrete shared backend API proposal

The future native radio owner supplies one completed `nsb_scan` generation plus immutable records and actual completion receipt. For every observation, this helper returns source-normalized `niwb_bss` (or an explicit omitted/refused-record count); it does not grant readiness. Backend exposes `begin_passive(generation, validated_channels, dwell_budget)`, `cancel(generation)` and immutable `snapshot(generation)` only after actual normal initialization/regulatory/worker receipts. Begin must reject existing active work, mismatched generation and unsupported channels before CID3 publication; cancellation must await real worker/DMA acknowledgment before releasing snapshots. A scan completion with no BSS is legitimately empty only after the matching completed transaction, never from an error or queue refusal.

The eventual IO80211 owner decodes exact versioned request options, checks its supported subset and maps Apple request/channel semantics only after those remaining numeric contracts are proved. It then calls the same backend begin API. On actual completion it converts metadata to a1164-byte record using separately proved Apple channel/rate flags, valid measured signal and age-unit mapping; no noise is invented. It freezes a result cursor, publishes event10 through an owned ring only after completion, and GET11 pulls that generation until actual EOF. Topaz current89451b8 patch0123's scan_start, WMI events and management BSS collection are useful equivalents to those backend boundaries; they do not supply the missing Apple numeric enums.

This keeps backend progress independent: implement real MTK passive scan and collect complete source-normalized records now, while refusing unproven iOS request variants. It does not require another diagnostic-only boot to guess a static Apple enum. The unresolved Apple adapter values are exact, finite integration prerequisites, not a request to fake availability.
