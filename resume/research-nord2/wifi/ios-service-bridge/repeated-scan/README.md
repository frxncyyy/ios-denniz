# Retained native repeated passive scans

Private integration candidate based on canonical source 97c2150d0f7e77b2a00af18a9c5d081017b00652 and successful VCN33 image 6a6a2ef79f03eaef540f4247016234217d5f8655b320c6afdf5dd81485c155ad. Host results are synthetic; this package has not run on hardware.

`proposed/` contains canonical-name replacements and two new files, `wifi_scan_service.h` and `wifi_scan_service_bind.inc`. Apply `integration.patch` to the shim; add both new files to the generator's copied NEW_FILES. No new BSD translation unit is required. Existing transport/RX TUs compile separately. The service binder is included at the end of the normal backend binder; the CAP worker calls its forward-declared continuation after the completed BASIC/normal batch and before the original park. The supplied transport binder is unchanged and need not be promoted.

Only `nord2wifiios=1` changes lifetime. Default off retains original boot26 and CAP worker park, never allocates the queue or invokes the ready hook. In explicit mode admission requires actual completed boot26/session, actual FW_READY, actual CAP/BASIC/board-address/regulatory receipts, the retained owner and clean complete scan. It release-publishes readiness then invokes `nord2_wifi_ios_backend_ready()` outside the queue gate. The service implementation must supply that C symbol. BASIC prints parking0; IOS OWNER replaces CAP WORKER park. This means a retained radio worker, not association or network connectivity.

The five public kernel-only functions in wifi_scan_service.h provide info, enqueue, cancel, immutable view and release. Four slots serialize requests on the actual CAP/radio worker. Count0 means the actual source-derived allowed passive set; a nonzero request must be a duplicate-free subset. The actual AIS board MAC and capability PHY fields are copied only by the kernel accessor, never logged. IOUserClient must independently validate its owning task/request, retain its client through completion, and compare the supplied client generation under its own gate before installing cache/events. A pointer returned by view remains valid until release; callers must finish all readers/conversion before release. Callback runs outside the queue gate. Release inside callback marks deferred retirement, physically freeing only after callback returns; the backend never accesses the cookie afterward. Queued cancel has zero radio I/O and no inline callback. Inflight cancel does not reset/abort/replay the published command: the bounded operation completes, then canceled cache admission is denied. No association API is added.

Each request seals exactly one CID3 from the existing checked scan builder and retained cap/board/channel inputs. It carries forward real TX index/packet sequence, software PSE capacity, event index and all five RX next/DIDX/segmented states. It never reinitializes firmware/DMA or replays boot commands. Packet/scan sequence and TX ring index may wrap; the monotonic completed counter refuses exhaustion before I/O. Credit remains the selected AXI software publication accounting, not invented firmware ACK credit. SCAN_DONE and actual BSS records retain their existing separate meaning.

Before publication a bounded drain requires an explicit whole five-queue idle pass with no pending DDONE. Zero delivered packets alone is insufficient. Up to256 passes/4096 frames are permitted, with existing bounded scheduler waits. Pending descriptor or exhausted stale-frame budget yields clean refusal without new CID3. Any already rearmed cursors/segmented state and actual transport RX index survive that refusal; only the closed command receipt is restored. A later request can continue draining. Pre-drain does not prove RF capture freshness, and host timestamps are processing times. Uncertain callbacks remain fatal.

A single static immediate-previous closed receipt anchors the next lease. Its older previous pointer is never recursively traversed; terminal validation checks only its own closed command records. This prevents an unbounded history while preserving the exact current owner identity. Pure preparation refusal restores the previous closed state without backend I/O. Scan timeout/event limit yields honest PARTIAL. Any uncertain native error sets common CAP/native/initializer/transport/FW halts, reports captured metadata, completes queued tickets with failure, then uses the existing30-second scheduler drain and panic/manual-reset policy; no recovery I/O/reset/retry.

Diagnostics contain only ticket/generation/state/count/error metadata. IOS OWNER is `active=1 retained=1 boot_complete=1 ready=1`. IOS SCAN fields are ticket,generation,status,sequence,frames,bss,done,partial,canceled,error,rx_error. Fatal IOS GUARD reuses captured reason/source/stage/error/valid/address/raw/mask/expected. No SSID/MAC/calibration payload is printed. Existing physical owner, coherent fault, unhandled SWINT29 and GIC policy remain unchanged.

Verification: `python3 test-native.py` uses canonical actual-owner fixtures and authenticated board input privately, Clang ASan/UBSan fail-fast. It exercises boot26 once plus250+ CID3 operations, packet/TX wrap, five-ring and segmented continuity, pending-DDONE refusal with stale rearm preservation, continuous incoming4096-frame refusal followed by success, zero-I/O preparation/counter exhaustion refusal and recovery, queued/inflight cancellation, slot capacity, deferred release, partial timeout, wrong DIDX shared halt/drain, and default off. `--log-dir` selects output; default writes no candidate files. `compile-owner.py` uses prior recorded normal ARM64 flags/cwd, substituting only source/output and sibling overlay, no extra include flags or forced NORD2; all five public symbols exist. `compile-helpers.py` compiles both changed TUs under recorded normal flags. Neither compile is a linked kernel or hardware proof.

The actual service registration, task/entitlement checks, Apple request conversion, result conversion/age, event producer and client-close synchronization are the separately reviewed service candidate. This queue is the concrete radio continuation it consumes. Initial cached GET alone is not a fresh UI scan; SET must enqueue a real request and completion must be generation-checked before notification.
