Channel and rate conversion boundary

`mapping.c` has no invented default channel table. It requires exact channel+flags mappings in both directions, refuses ambiguous duplicates and retains unsupported attributes as refusal. A native mapping table still needs independently proved iOS band/width flag semantics plus current MTK regulatory channel receipts. Framework bit13 is specifically tested along the six-GHz path, but that is not proof of every other band flag. No rule deriving all bands from channel number is supplied.

The result conversion at0x1d3ebd26c–2cc classifies numeric rate categories {6,9,12,18,24,36,48,54}, {1,2,5,11}, {22,33};d5cc–5dc exports each raw32-bit rate as a CFNumber without scaling. The pure mapping helper strips the IEEE basic-rate bit, uses an explicit separately established table, deduplicates and refuses unknown entries atomically. Its synthetic test table is not a production rate policy.
