# Root-only promotion recipe

Copy the twelve files in promotion.json byte-exact into shim/nord2-xnu and generated xnu/bsd/dev through the existing generator. The five new C modules are wifi_wpa2, wifi_wpa_crypto, wifi_station_transaction, wifi_wpa_owner and wifi_wpa_nst; each needs its standard bsd/conf/files entry. Transport v4 separately supplies wifi_station_wire/transport C/H, source-layout header and two native bind/forward includes. Bridge v3 supplies wifi_ios_join/station_view and wifi_station_service.h; root supplies wifi_ifnet_link.h/inc. Preserve both NOTICE and BearSSL license in the canonical source documentation. Do not use frozen generic transaction/crypto_provider filenames.

Apply transport v4 owner-guards.patch to wifi_normal_backend_forward.inc and wifi_basic_config_bind.inc. The private wifi_scan_service_bind.inc is a complete replacement of the current NSS binder: it includes wifi_station_transport_bind.inc, then wifi_station_service_bind.inc after NSS delivery definitions, before its existing owner loop. Forward declarations precede admission/start/delivery. No new worker or boot replay exists. Production registration retains the sole nord2wifiios opt-in. Existing NSS_HOST_TEST fixtures explicitly keep disabled station stubs unless NJS_HOST_TEST is selected; the dedicated station service fixture compiles the real service binder.

The generator MAIN_FILES must contain the five new C modules plus the transport pair; its include loop must copy station service/transport forward/bind and source-layout header. Generator MAIN_FILES and include loop currently already contain these names in root's prepared edits; verify rather than duplicating entries. All C modules reside in bsd/dev. The provider's kernel-only relative BearSSL includes resolve from bsd/dev into the existing xnu/libkern/crypto/sweet_bearssl/inc tree. Existing sweet_sha1 and sweet_aes_ct_cbcdec wrappers already provide the primitive symbols; no alternate provider or duplicate primitive definitions are required.

Copy proposed/tools/test-nord2-wifi-station.py and its fixture directory into tracked tools. The default runner uses canonical shim sources. --candidate selects this private overlay; --bearssl can select the pinned staged source tree. Deterministic public IEEE/RFC/synthetic vectors are stored in the fixtures, so the portable runner does not need Python cryptography. No board/network credentials are required.

After root generates the actual buildtree, run compile-native.py --canonical --output <private verification directory>. It compiles the actual recorded sweet_touch.c plus seven new helper C sources with original selected kernel flags and no private overlay. Default mode uses a temporary private overlay; do not misreport that as canonical equality. Root separately compiles client/registry and performs linked/source/ISA audits. No image/device/CI/gate actions are performed by these scripts.

First station attempt consumes this boot epoch. New joins and offchannel scans are refused after it; no same-peer firmware retirement or return-to-NSS receipt is invented. Ordinary wrong-key/integrity/auth/assoc/EAPOL timeouts close port and complete bounded cleanup with an ordinary failed result. Only actual native IO/lease/operation uncertainty follows the inherited retain/drain/halt policy. Preserve these limitations in the image handoff.
