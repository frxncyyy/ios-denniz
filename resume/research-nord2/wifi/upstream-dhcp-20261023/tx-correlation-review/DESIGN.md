# Independent design constraints (candidate implementation pending)

Sampled PID domains management1..31/security32..63/data64..126 must be disjoint and boot-lifetime, never reinitialized by native generation/preparation. Fallback127 is permitted only for host-only security/data diagnostics and must remain explicitly ambiguous. Air-correlated management cannot use fallback127 or a previously published ID; exhaustion must refuse before publication. A bounded monotonic global allocation or persisted owner-global ledger is needed. Current first-connection limitation does not justify silently resetting these values.

Reserve/consume an ID before any potentially committed publication. Bind attribution only when the actual descriptor/selected PID/WLAN and published operation are known; successful metadata formatting or admission is not publication. A potentially committed failed write must never free its ID. Record immutable generation/submission/kind/public class/PID/WLAN for sampled IDs; do not correlate using current last_pub/last_kind. Old-generation, wrong-WLAN, duplicate and unassigned events must never acquire current-packet meaning. Record first matching TXS once; subsequent duplicates are explicitly non-new observations, not new successful transmissions. An event before publication cannot prove reception.

No changes to air_pending, management TXS completion, normal HW0 DDONE/token lifetime, security/data local-submission receipts, keys/port, authorization or lease state. Diagnostics are observational even on firmware status0. Advanced fields retain validityflag semantics; no packet identity or credentials in logs.

Minimum useful tests: exact boundaryIDs, exhaustion/fallback, multiple native generations, prepublication failure and uncertain commit, delayed old events, wrongWLAN, duplicate, earlyevent, security/data domain collision, optional hostTXS before/after local retirement, and unchanged control/ownership transitions. Root's reader must distinguish source correlation from shared127 historical ambiguity.

# Accepted OFLD frame classification

Use an independently reserved small budget (e.g. first4 or8 accepted OFLD frames per generation) so ordinary multicast cannot consume it. Carry only OFLD numeric metadata through deferred event state; classify EtherType and existing bounded UDP/DHCP classes only after the entire existing secure decode has accepted the frame and RX descriptor has been rearmed. Existing nsdd_receive is the appropriate lifetime boundary: bytes remain in owned rx_frame and classification executes before callback/reuse. Do not read rejected payload or treat fixed RXERROR metadata as authenticated Ethernet. Output numeric OFLD/EtherType/length/destinationclass/UDP-or-DHCPclass; no MAC/IP/XID/options/raw bytes. Native accepted RX does not prove BSD delivery, authenticated DHCP exchange or lease. A separate line avoids silently overloading historical DATAHDR budget/schema.
