# Independent audio candidate review — changes required

Reviewed Claude's private candidate and source-pinned report read-only. Candidate/docs SHA256 values were unchanged across the single inspected host-test run; snapshot.json records exact before/after hashes. No device, active/canonical source, integration, CI or audio-worker edits occurred.

## Blocking findings and narrow revisions

1. **I2C8 takeover has no controller/ownership preflight.** audio_id_bind.inc:94–126 accepts pad mode1 or GPIO input and changes DOUT/DIR/IES/MODE before nau_run:439 checks line levels. No I2C8 or APDMA controller aperture is mapped or read. Mode1 is the normal controller function, not evidence of idle. An active controller can have both lines high at a sampled point, and changing the mux can release a line before the core even checks it. Saved live DT:9466–9488 identifies I2C8 at11d04000 and APDMA at11000780, plus default/CCU channel offsets100/200; DT:9509–9529 includes enabled always-on DDR/UFS bucks51/56. Binding simulator assumes the mode1 controller releases lines (fixture:71–74), so passing wire allowlist tests cannot establish this precondition. Required: controller/bank/DMA and clock-access source-backed idle/exclusion contract before the first pin mutation; refuse uncertain/busy/stuck state without any edge or mux change. Do not enable/reset/stop an unknown controller just to inspect it. Capture original pad levels before takeover under valid IES and assert bus-free stability, while retaining explicit software ownership. If that cannot be made concrete narrowly, retain a snapshot-only milestone and skip I2C8 entirely until reviewed native hardware-controller transport exists. A high-pad snapshot alone is insufficient.

2. **Automatic fault recovery continues after an uncertain transaction.** audio_id.c:317–336 ports Linux generic SCL recovery; nau_run:443 may recover then probe the other amplifier. nau_read16:303 also attempts STOP after stretch/protocol failure. The software address allowlist proves only bytes deliberately sent from an initially synchronized bus. It does not prove that mux takeover or an interrupted frame cannot clock an inherited transaction. Linux i2c-core-base.c:186ff explicitly uses the owning adapter's optional prepare_recovery callback; the candidate has no corresponding controller handoff. The generic recovery algorithm's source and clean simulated frame cases are useful, but do not establish shared DDR/UFS transaction preservation here. Required for this diagnostic: remove automatic recovery pulses and subsequent-amplifier continuation after uncertain faults; define a sticky uncertain result and exact fail-stop line/mux policy. Clean NACK/verified STOP can remain a distinct bounded result. Do not claim uncertainty is resolved merely because lines later rise or saved pin registers verify. Test interruption at each wire phase against an already active/inherited frame, not just a clean-start amp simulator.

3. **Sticky halt can be bypassed on Linux return.** header:157 promises halt or busy must refuse return and leave I2C8 untouched. Yet nab_prepare_return:238–242 tests busy only; with halt1/changed1 it retries pin restoration, and if the later writes succeed returns true. Existing fixture:410–421 holds the write fault permanently, masking this path. Required: refuse halt or busy before any callback; add transient restore failure test proving prepare_return returns false and adds zero MMIO callbacks after the halt, even if hardware would accept later writes. The separate question of whether any post-uncertainty mux restore is safe must be decided by the transport contract, not arbitrary retry.

4. **Unknown REV still triggers family-specific register reads.** nau_probe_amp:374–387 reads00/13/14/15/16/17 before nau_decode recognizes only73/74. The unknown1234 fixture explicitly expects full successful reads. Board CONFIG and generic nxp,tfa98xx compatible do not establish a 9873/9874 instance. Selected Android tfa98xx.c:5076ff dispatches by revision and supports multiple families. Required: after REV, whitelist supported full/low-byte revision policy per selected source before additional registers. Preserve unknown raw REV, classify unsupported, stop that amp without interpreting or touching other register pointers. Alternatively restrict this milestone to REV only. This is a source-evidence gap about side effects on unknown models; no hardware harm is claimed as observed.

## Host test result

Executed candidate/tools/test-nord2-audio-id.py once with CC=cc, CROSS absent, inspecting its temporary ASan/UBSan-only runner first. Core fixture aborts at line279 in test_stuck_sda_before. Binding fixture is not reached. Exact output is host-test.log; returncode1.

The first assertion likely has a fixture baseline error: sim_init leaves SCL/SDA high; assigning dev[3].stuck_sda=1 then sim_update creates an SDA falling edge while SCL high and increments bus.starts before nau_run. The test nevertheless requires absolute bus.starts==0. Fix by recording counters after injecting the inherited condition and asserting they do not change during the probe, while retaining transactions0/line_ops0 assertions. Do not relax the safety invariant or treat this as evidence that the production core transmitted. Worker should rerun the complete suite after that fix and the ownership/fault revisions; this review did not patch or skip the failing test.

## Useful parts retained

Default-off returns before mapping, static state, exact PA/read-pointer tables, separate cold AFE guard, no amplifier reset/clock/power/DMA writes, and explicit family decoding are good foundations. The report identifies the real shared bus and distinguishes native diagnostic from usable iOS audio. Those do not remove the takeover blockers. Documentation calling the whole milestone read-only must specify GPIO/mux and wire mutations. The binding comment that a stuck I2C8 is harmless to iOS is unsupported when that bus includes DDR/UFS supplies, even though iOS has no controller driver.

Integration guide's generator wrapper must use board_config before NORD2 guard, and validation must compile without forced -DNORD2, as already discovered for battery helpers. No audio integration is approved by this source review. Next useful change is a small safety-contract revision or snapshot-only split, not tone/DMA/HAL expansion.
