# Private current-source audio-ID integration proposal

This bundle rebases the reviewed audio revision 5 ID probe onto repository source commit `88588a074718e54dd4f1fa63142c304899fff0f4`. It changes **only private copies** of the generated `bsd/dev/sweet_touch.c`, `bsd/conf/files`, `tools/nord2-mkpatch.sh`, and proposed audio sources. `integration-current.patch` contains the three edits to current source/generator/conf; `prepare-private.py` reproduces them after checking exact input hashes. Do not run the proposed generator copy to make an image or modify the active buildtree.

The hook remains `nord2audioid=1` for a nonmutating MMIO snapshot or `nord2audioid=2` for the bounded hardware I2C8 PIO amplifier-ID read. When the argument is absent or any other value, `nab_audio_id()` returns before mapping or MMIO. A host fixture explicitly proves that default-off path has zero reads, writes, maps and logs. The mode-2 binding restores only same-transaction captured AP-channel configuration, and uncertainty refuses Linux return. The shared I2C8 DDR/UFS rail is not bit-banged, reset or reconfigured outside that reviewed bounded path.

The binder reports `naf_gate()` and `naf_pll_pcw()` only from captured state. The generated `audio_afe.c` is present to resolve those pure calls, but **`naf_cycle()` has no call site**. There is no AFE clock/power/SRAM write, silent-stream run, analog amplifier output or working-audio claim. The existing hook follows `ni_wifi_power_probe()` in the input thread, as in the reviewed diff; a radio panic before that call can prevent audio evidence. Any future hardware image requires separate exact user authorization and source review.

`python3 research/nord2/audio/id-integration-current/verify-private.py` passed. It applies the proposal in a temporary private tree and checks byte-exact output, then compiles the copied whole `sweet_touch.c` and all three wrapped audio translation units with CI-derived `DEVELOPMENT ARM64 SWEET` flags and normal exported headers from `research/ci-39398655023/buildtree`. The latter export has `NORD2` in `SWEET.h` (SHA-256 `2d69309e...`) and produces nonempty objects; `sweet_touch.o` has unresolved calls to `nau_run`, `na8_probe`, `naf_gate` that the three audio objects define. The host ASan/UBSan binding fixture also passes. Existing nonaudio includes for the current `sweet_touch.c` are resolved from the current generated `research/ci-39158169212/buildtree/xnu/bsd/dev` directory; this is an explicit mixed-harness qualification, not a full current CI link or boot test.

An initial compile against the older CI-39158169212 exported `SWEET.h` produced empty `#if NORD2` objects despite exit status 0. That result is rejected as verification; the newer normal CI export and positive symbol checks are mandatory. Nothing in this bundle was integrated into active source, sent to CI, placed in an image or run on a device.
