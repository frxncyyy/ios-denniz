## Decision and remaining evidence

The full audit and cross-review identified **two demonstrated stop/ownership ordering defects**, now corrected in the private candidates below, in addition to inherited-I3C false refusal. No other fatal amplifier defect was established. This is not evidence that physical startup works: the actual last boot stopped at I3C_EN=0x8800, before REV/reset/CLKS/profile/output writes. The next run can still encounter unavailable amp supplies, a different REV, unavailable TDM clocks, or real bus faults. These are specifically observable gates, not reasons to guess new PMIC or hidden-register writes.

Three material differences/limitations remain explicit:

1. **Software I2CR omitted:** Android tfa_dsp.c611–633 resets all I2C defaults before each cold silicon init; port instead externally resets HIGH5ms/LOW5ms before each complete lifecycle (audio_hw.c171–206, reset restored after stop). External reset matches Android's probe reset tfa98xx.c4740–4749, but source alone does not document equivalence of every register/MTP-shadow default. This is a potential cold-default assumption, not a demonstrated failed register. A future exact-parity correction would issue documented I2CR reg00bit1 with full reset value2 *before* silicon unlock, recheck PWDN1/AMPE0, and then reapply the whole profile. Do not blindly add it after configuration: it would erase tuning. A meaningful test must model I2CR erasing prior profile and assert its location before all errata/profile writes. Existing external reset plus state gate is a plausible implementation for the bounded first test; parent must explicitly resolve this difference rather than label it byte-identical startup.
2. **Container unlock preamble is not replayed verbatim:** selected device lists begin reg0f=5a6b, rega1=5a, rega0=5a. Port executes the silicon challenge rega0=FB^5a and the documented KEY2 unlock, keeps KEY2 unlocked through all board settings, then locks. Android tfa_init.c896–901 + tfa_dsp.c819–830 establish challenge/KEY2; tfa_container.c1210–1242 would additionally replay the container's three writes. No public-source explanation proves the extra fixed rega0=5a required or harmful. All protected board masks have readback, so refusal will fail closed. Do not reinterpret the fixed value as the silicon challenge, or alter hidden keys speculatively; this remains a documented parity deviation for hardware agent review.
3. **Speaker protection DSP is absent by design:** this path drives low-level PCM directly; it does not implement Android's host SmartPA algorithm, impedance delivery, adaptive noise mode or calibration. Android tfa98xx.c4320–4393 reads MTP_RE25/MTPEX and sends calibration to MTK DSP; playback calls it at4447. mt6893.dts8055 sets `swdsp_smartpa_process_enable=<5>`. That is a product-quality/protection gap, not proof of a digital-unmute prerequisite: proBus OPERATING explicitly sets AMPE, and selected speaker profile is register-only. Current ceiling256/32768 yields at most256 magnitude from signed16 full scale (~−42dBFS), tone adds another6dB attenuation, diagnostic lasts1s. Continuous HAL mode has no fixed total-duration ceiling while fresh PCM arrives; therefore it must not be described as equivalent to Android's protected loudspeaker implementation. Do not program MTP or run calibration to obtain a first tone.

## Concrete stop/ownership bugs and proposed correction

Parent/profile cross-audit identified a real bounded-ring defect: normal stop mutedamp0 then waited up50ms before mutingamp1; DMA ring21.33ms can replay stale data inamp1 while worker blocks. Candidate `audio_hw.c` first clears/readbacks BOTH AMPE, then uses existing bounded cold/powerdown/lock. Any unverifiedmute skips waiting and reaches existing localreset fallback. No next-slave transfer after offline/uncertain.

A second demonstrated ordering defect: fatal DMA deadline, invalidpointer and stalledclock used normal stop, allowing blocking I2C/state polls before removing excitation from an already unowned ring. Candidate `terminate` asserts/verifies alreadyowned GPIO111/148 reset immediately, closes ownedAFE with no amplifier/I2C access, latchesuncertain+stop_error, clearsrunning/queue and preservesreset/clockownership for inspection. Silent diagnostics skip amplifierreset. HealthyUSB/status paths remain untouched. Normalidle/userstop keeps normal both-muted-first path.
