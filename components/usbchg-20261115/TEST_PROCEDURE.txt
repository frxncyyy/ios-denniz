q10jfinal14usb test procedure (usbchg-20261115, pieces 0700 USB-less boot, 0701 gauge/report, 0702 MP2650 charge control)
Phone actions are for the main session only.  Checker: python3 -I gpu/build/usbchg-20261115/usbchg_check.py <xnu-live.log>

Battery guard (every step)
- Start only with the gauge >= 30 % (last NORD2 BAT14 shown=, or the iOS status bar) and battery < 40 C.
- Stop discharge-type steps at 20 % (BAT14 shown=20 or mv < 7000 = 3.5 V/cell): put the phone on the wall charger with
  q10jfinal14usb running (step 3); if 0702 does not charge (avg stays < 0 with the screen off), flash back q10jfinal13 and
  charge with the screen off, 2 A wall charger; never leave it below 15 %.
- Abort charging and unplug if BAT14 temp > 45 C, a "NORD2 CHG14: ... FAILED"/"latched" line appears together with avg > +2500 mA,
  or pack mv > 8900.  0702 itself turns charging off at >= 50 C and at pack > 8900 mV.

1. Normal boot with the PC cable (as usual: flash_boot.sh, txn/live log).  Expect:
   NORD2 USB14: console up at boot (host cable present)
   NORD2 CHG REGS / NORD2 CHG CFG (first sample: the configuration LK left: ilim, ichg_set, vfloat, chg_en, learn(hiz), wdt)
   NORD2 CHG14: type=usb host ... target=500mA, then writes REG08/REG09/REG02 as needed ("write REGxx=yy ok")
   NORD2 BAT14 every 60 s: shown/raw SOC, rm/fcc, cur/avg (+ = charging), pg=1 state=2 (fast) or 1 (pre), ios ext=1 charging=1
   iOS: lightning bolt in the status bar while the cable is in.
   On a PC port 500 mA x 5 V is less than the load with the display on: avg < 0 is expected with screen on; with the screen off
   for 5 min avg should go positive.  (Optional: sysctl kern.n2chg_sdp_ma=900 for a USB3 port; never above 1500.)
2. Unplug the cable for 2 min, replug: CHG14 type=none, then deciding -> usb host (host events), ilim back to 500; BAT14 ext 0 -> 1.
3. Wall charger (the console is still up from boot; plug the wall charger instead of the PC; logs come later via the rescue
   tail or after replugging the PC): expected CHG14 type=charger, ilim ramps 500 -> 1000 -> 1500 -> 2000 mA in 10 s steps while
   vin >= 4.6 V (a sag below 4.5 V steps back and caps), ichg 1100 mA at 10..45 C.  After 10-15 min on the wall charger with
   the screen off the SOC must rise (BAT14 shown/raw up, avg ~ +900..+1100 mA).  This is the real check of problem 1.
4. Boot WITHOUT any cable (problem 3): power on unplugged, wait 90 s for the lock screen, then plug the PC:
   - success = iOS reaches the lock screen/home and stays up (before 0700 it left XNU at "NORD2 USB: clock gated" -> LK fastboot);
   - the boot log is in the persistent log: ENTER=1 FB_WAIT=120 bash gnss-20261114/sweetlog_tail.sh /tmp/OUT 300 only after a
     crash; otherwise the live console will NOT appear (no console without LK's USB init) -> read it next boot or via rescue tail.
     Expected lines: "NORD2 USB: clock gated" (or "device inactive"), "NORD2 USB14: no usable USB at boot (why=3 ...)",
     "NORD2 USB14: late check ..." every change.  Charger: type=unknown source, target 1500 mA.
   - optional late console (EXPERIMENTAL): sysctl kern.n2usb_late=2 in that boot, then plug the PC: "NORD2 USB14: power-up
     clocks ..." and hopefully "late console up"; if it does not come up, nothing else changes.
5. Percentage behaviour (problem 2): over a 20-30 min session, BAT14 lines every 60 s (or each change): shown follows raw within 1 %,
   no shown=0 blips (a failed gauge read now gives stale=1 with the last value, fails= counts them), iOS status bar % equals shown.

Kill switches (sysctl, runtime): kern.n2usb_strict=1 (old stop behaviour), kern.n2usb_late=0, kern.n2bat_legacy=1 (old
IOPMPowerSource publishing), kern.n2chg_pg_active_low=1 (old charger polarity), kern.n2chg_ctl=0 (no charger writes, observe only).
Whole fallback: q10jfinal13 (only these 3 pieces differ).

0703 (q10jfinal14usb2 / q10jfinal15): plug/unplug latency.  Unplug and replug the charger 3 times, >= 5 s apart, display on.
Expect per edge "NORD2 BAT15: VBUS OFF|ON at t=...ms (fast check, edge N) -> immediate refresh", then "published pg=0|1 <n>ms after
the edge" (n ~ 5-40 ms for the first refresh, then +1 s / +3 s follow-ups), a BAT14 line with ios ext=0/1 at the same time, and the
iOS bolt changing within ~1 s.  Kill switch: kern.n2bat_fast_ms=0 (back to the 10 s full-sample timing).
