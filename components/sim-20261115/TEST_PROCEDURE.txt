q10jfinal16sim (= q10jfinal15 + 0710 SIM/PIN + 0711 generic APN + 0712 NR reporting) -- on-phone test steps (main session only)
Image: gpu/build/device-mmu-q10jfinal16sim-candidate/ui-sched/nord2-ios-metal-q10jfinal16sim-*.img ; flash like q10jfinal15
(autocycle/flash_boot.sh <img> with the phone in fastboot), userland unchanged (gfxall16-seeded).
Log markers (USB live log / sweetlog): "NORD2 SIM:", "NORD2 APN:", "NORD2 NR:", plus the existing "NORD2 BB: modem state #".
Kill switches (sysctl, runtime): kern.n2sim_fix=0 (all of 0710 off), kern.n2sim_apn=0 (0711 off: internet.it for every SIM),
kern.n2nr=0 (0712 off). Read-only state: kern.n2sim_state, kern.n2nr_state. Fallback image: q10jfinal15 (70f31e50...).

A. Very SIM (regression, must behave exactly as final15)
  1. Boot with the Very SIM. Log: "NORD2 SIM: +CPIN "READY" -> state 1, shown to CommCenter 1", then
     "NORD2 APN: SIM of PLMN 22288 (Very/WindTre): internet.it / mms.it as before", "NORD2 BB: IMS setup (0277aw): 52 AT commands",
     "NORD2 APN: modem APN table synced with internet APN "internet.it" (setup)", "NORD2 BB: PDN bring-up #1 (APN "internet.it")".
  2. Settings: carrier name Very, bars, 4G; Safari over cellular (Wi-Fi off); SMS in/out; one call; MMS if possible.
  3. NR: "NORD2 NR: reporting enabled", "NORD2 NR: AT+E5GOPT? -> OK [+E5GOPT: N]", and while downloading (Safari/App with traffic,
     Wi-Fi off) watch for "NORD2 NR: URC +ENRCABAND: 1,78 -> NR leg UP, band n78" (= modem on 5G NSA). iOS will still show 4G/LTE.
     Report every "NORD2 NR:" line and kern.n2nr_state (0x8000xx01 = NR leg up).
B. Other operator's SIM (the one that asked for a PIN)
  1. Power off, swap SIM, boot. Log: "NORD2 SIM: +CPIN "<token>" -> state S, shown to CommCenter X" -- PLEASE COPY THESE LINES:
     the token tells the root cause (expected READY; "SIM PIN2"/"SIM PUK2" = the 0277 bug fixed by 0710; "SIM PIN" twice in a row with
     PIN-lock 1 = the card really has its PIN on).
  2. Expected: no PIN sheet. If the card really has a PIN, iOS asks for it; entering it now works: "NORD2 SIM: UIM Verify PIN (PIN1) ->
     AT (digits not logged)" then "-> OK (err 0x0), retries PIN1 3 PUK1 10" and the card goes ready. Wrong PIN: "-> failed (err 0xc)".
  3. APN: "NORD2 APN: SIM of PLMN 222xx: waiting for CommCenter's APN", then "NORD2 APN: internet APN "<apn>" (from CommCenter profile|
     Start Network)", "modem APN table synced with internet APN "<apn>"", "PDN bring-up ... (APN "<apn>")". Cellular data in Safari.
     If no APN arrives within 45 s: "no APN from CommCenter 45 s after the SIM was ready" -> set the APN in Settings > Cellular >
     Cellular Data Network, then expect "APN table update for "<apn>"".
C. Hot swap (optional): with iOS running remove the SIM -> "NORD2 SIM: card gone (+CPIN: SIM not inserted|+ESIMS: 0): its IMSI/ICCID/
   GIDs forgotten"; insert the other SIM -> its identity is read again (modem state "IMSI cached, ICCID cached"), setup runs again.
D. No SIM: Settings > General > About still shows "Carrier Very 54.0" -- NOT fixed in this image (CommCenter's own last-known-carrier
   cache, see NOTES); only check that the log says "shown to CommCenter 4" (absent) and kern.n2sim_state low byte 4.
E. Every 60 s report: "NORD2 SIM: report t=... state 0x... card swaps N, PIN operations N; APN "..." (...), NR state 0x...".
