# Kernel patches 0095-0096 (host-only, not flashed; P5v/P6 images)

## 0095 short boot-arg aliases
The inherited UI command line is 600 of 607 characters. `n2lvts=<n>` == `nord2_lvts=<n>`, `n2mhz=<MHz>` == `nord2_gpu_khz=<MHz*1000>` (100..1000 MHz). Full names win. `nord2wifiemi=0` was dropped from the P5v/P6 images: `wifi_emi_probe.c` treats an absent argument and `=0` identically (mode 0, refused).

## 0096 CPU-access tracking: remove per-job cache maintenance
### Evidence (c6k probe350, 129 jobs / 2 s, stats line of 0089)
`run_us` 100 avg, but `q_us` 1005 (`clean_us` 996), `inv_us` 992, `ret_us` 2107, `clean_KiB = inv_KiB = 2,129,760` = **16.5 MiB cleaned and invalidated per job**. `gap_us` (submit -> WAIT entered) = 1049 shows the clean runs inside `submit`.
Cost model from these numbers: about 0.24 us per 4 KiB page per direction, i.e. 2744 pages (one 11 MB display surface) = 0.65 ms each way.
Where the 16.5 MiB comes from: every job lists the persistent tiler heap, which the diagnostic tiler matrix allocates at 16 MiB and the bridge maps for CPU inspection (UI runs use the 2 MiB default heap), plus the imported display surfaces and small mapped buffers.

### What was wrong in principle
The 0087 scoping cleaned and invalidated EVERY listed buffer on every job. That is only needed for buffers the CPU can still hold dirty lines of (clean before the GPU reads) or can read after the GPU wrote (invalidate). A buffer the CPU can never reach needs one clean (the kernel's own zero fill) and nothing else.

### Design (per-buffer state in the core; levels set by boot-arg `nord2_gpu_track` / alias `n2trk`, default 1)
State per buffer: `cpu_dirty`, `cpu_visible`, `explicit_track`, `gpu_dirty`, `gpu_written`.
* **Level 0**: 0087 behaviour (every listed buffer, every job).
* **Level 1 (default, no userspace change)**: a buffer becomes `cpu_visible` only when the driver hands out a user mapping (`clientMemoryForType`) or when it is an imported surface. Invisible buffers (tiler heap, TLS/WLS, anything the bridge never maps) are cleaned once, then skipped for clean AND invalidate forever.
  A buffer that becomes visible after the GPU wrote it is invalidated once at that moment (a speculative fill of the kernel alias cannot leak stale contents). Visible buffers are maintained exactly as at level 0.
* **Level 2 (`n2trk=2`)**: imported IOSurface buffers are `explicit_track`: no per-job maintenance. The CPU-access protocol is the IOSurface one:
  * `IOSurfaceLock` (kernel `trapLock`) and the framebuffer copy in `present()` call `nord2_gpu_surface_cpu_acquire`: invalidate the surface only if the GPU wrote it since the last acquire.
  * `IOSurfaceUnlock` without `kIOSurfaceLockReadOnly` calls `nord2_gpu_surface_cpu_release`: marks the surface CPU-dirty so the next GPU job cleans it (once).
  * The GPU invalidate is deferred (`gpu_dirty`) instead of done per job. Strong/weak symbol pair: `SweetSurface.cpp` carries weak no-ops, `Nord2GPU.cpp` the real definitions (verified in the linked kernel).
* **GPU-only allocation flag** (userspace, optional): `ALLOC` flags bit1. The kernel refuses any CPU mapping of such a buffer (`clientMemoryForType` returns not-found, `n2c_bo_cpu_visible` returns E_STATE), so "never maintained again" is enforced, not assumed. Needed where a buffer would otherwise be mapped for diagnostics (the matrix heap) -
  the bridge should allocate the heap/TLS/private targets with bit1 and only drop it when it deliberately maps them. Rejected combinations: with IMPORTED or CPU_UNCACHED.
* Full-maintenance jobs (legacy compute ABI, a full 32-handle list, the `nord2_gpu_cache=1` valve) ignore tracking and reset the state (clean everything, invalidate every GPU_WRITE buffer, `gpu_dirty` cleared).
* Explicit syncs (`SYNC` selector, `n2c_bo_sync`) are unchanged.
New counters on the JOBS line: `trk=<level> skipC_KiB skipI_KiB defI_KiB acqI_KiB` (clean KiB skipped, invalidate KiB skipped, invalidates deferred to a CPU acquire, KiB actually invalidated by acquires).

### Coherency analysis of the display path
The display panel is not DMA-fed from the GPU's surfaces: `SweetFramebuffer::present()` copies the winning layers' pixels with the CPU (through the surface's kernel mapping, default-cached) into the physical, write-combined panel buffer. So the only consumer that needs the GPU-written lines is that CPU copy: one acquire per present replaces one invalidate per job. CPU producers (CoreAnimation software layers, widgets) write under `IOSurfaceLock`; their unlock marks the surface dirty.

### Expected effect
Per job maintenance drops from ~2 ms (16.5 MiB each way) to the cost of the small visible buffers (command block 32 KiB, code, vertex data: tens of pages = about 10-30 us each way) plus, per CPU lock or present, one invalidate of the surface the GPU wrote (about 0.65 ms for a full-screen surface, once per frame instead of once per job).
UI frame with ~200 jobs: from ~400 ms of maintenance to ~5 ms + 1-2 ms. The probe run itself will improve only if the bridge stops mapping the matrix heap or allocates it GPU-only; with the heap mapped (diagnostic), it stays conservative by design.

### Risks
* Level 2 relies on the IOSurface lock protocol: a CPU reader/writer that touches an imported surface without Lock/Unlock sees stale GPU data or loses a write. The probe's direct pixel checks use `IOSurfaceLock(ReadOnly)`; the frontend's own CPU access needs the same audit (posted on the board). `n2trk=1` or `nord2_gpu_cache=1` restore the safer modes without a rebuild; probe350t1 is the A/B image.
* Weak/strong symbol override and a locally compiled `SweetSurface.cpo` (CI member recompiled with the local clang, like `SweetFramebuffer`).
* `trapLock` now takes the GPU driver lock briefly (and invalidates under it when the GPU wrote the surface).
