# Kernel patches 0110 and 0111 (host-only, not flashed; P13 images)

Numbering: the coordinator's "0107" (cache scope) and "0108" (trap path) collided with documents/patches already issued under those numbers (0107 = the CPU DVFS design note, 0108 = the WAIT_SEQ(0) fix, 0109 = the MCUPM read-only probe), so they are **0110** and **0111**. The images are built on the cumulative series (0100-0106, 0108-0111), not on P9 alone: 0108 is the root-cause fix for "one job per wait" and the patches are not independent of the shared `Nord2GPU.cpp`.

## 0110 post-job invalidate follows the job's declared writes (opt-in `n2wm=1`, alias of `nord2_gpu_wmask=1`)
What the device logs show (`NORD2 GPU JOBS`, c6l/c6o `ui350`/`ui60`): `full=0` in every window, so the whole-context path (`full_maint`) is NOT what costs ~600 KiB per job; the scoped path is. `clean_KiB/jobs` ~ 560-620 KiB and `inv_KiB/jobs` ~ 540-600 KiB, i.e. the same listed buffers are cleaned before and invalidated after every job. They are the buffers a job lists that the CPU can see (client `MTLBuffer`s: vertex/uniform/argument data, command blocks) and that are mapped `GPU_WRITE` (a Metal buffer may be written by any shader, so the bridge maps them read-write): the kernel cannot know which of them a job really writes, so it invalidates all of them (0087 chose the list, not `write_mask`, because v1 compute set the mask conservatively).
Change: with `n2wm=1` a job with a **non-zero** `write_mask` invalidates, and marks `gpu_written`/deferred-dirty, only the listed buffers whose bit is set; the others are counted in `cache_skip_wmask_pages` (JOBS line `wmI_KiB=`). `write_mask == 0` ("declared nothing") keeps the conservative rule, `FULL_MAINT`/full-list/valve jobs ignore the mask. The set is fixed before the first buffer exists (like the tracking level).
Unchanged on purpose: the clean (CPU -> GPU) before the job. A buffer the job only writes still needs its dirty CPU lines written back first, otherwise a later eviction would overwrite the GPU's output, and the kernel has no read mask. The clean is where the remaining ~560 KiB/job sit; shrinking it needs CPU-write spans from the bridge (ledger E8) or uncached/WC mappings, not a kernel guess.
Correctness contract (opt-in): the bridge's `write_mask` must contain every buffer a job can write. It is already relied on for GPU-complete present gating (0097c). If it ever under-reports, the CPU can read stale lines of that buffer: the symptom would be old data in a buffer the GPU wrote, only with `n2wm=1`.
Expected gain: at most the invalidate cost, ~36-40 us per job of ~600-900 us (4-6 %), proportional to how many listed buffers are not declared. Measure with `wmI_KiB` (skipped) next to `inv_KiB` and `inv_us` (c6o baseline 36 us).
Tests (`nord2_core_test.c`, scenario 23 `test_write_mask_invalidate`, ASan/UBSan; mutants killed: mask ignored, zero mask narrowed, bit sense inverted, mode forced on): in both modes the GPU-reads-CPU-written direction (both listed buffers cleaned, whatever the mask) and the CPU-reads-GPU-written direction (declared buffer invalidated), the other half of the mask, `write_mask == 0`, both bits, `FULL_MAINT`, refusal after buffers exist, and a tracked display surface at level 2: undeclared -> no deferred GPU write and a CPU acquire invalidates nothing; declared -> deferred, acquire invalidates it once; CPU write (unlock) -> cleaned again by the next job even though the job does not declare it.

## 0111 IOConnectTrap6 fast path (the kernel half of ledger #12)
ABI = the frontend's probe in `gpu/metal/tegu/nord2_transport.inc`: `IOConnectTrap6(conn, 0, &call, sizeof(call), 0,0,0,0)` with
`struct nord2_gpu_trap_call { u32 magic 'N2TC', selector, scalar_in_count, scalar_out_count; u64 scalar_in[4], scalar_out[4]; u64 struct_in, struct_in_size, struct_out, struct_out_size; i32 result; u32 done 'N2TD'; }` (120 bytes, byte-identical to the frontend's copy: the host test compares every offset).
Kernel (`Nord2GPUUserClient::getTargetAndTrapForIndex` + `trapCall`): index 0 only. The call block is copied in and checked (`nord2_gpu_trap_call_ok`: size argument == 120, magic, `done == 0`, <= 4 scalars each way, struct_in <= 16384 bytes (the LOG bound), struct_out <= 256 bytes, no size without pointer); struct_in is copied into a kernel buffer; the reply memory is proven writable BEFORE anything runs (a refusal after the method ran would make the frontend repeat the request through MIG, i.e. a double SUBMIT); then the very same `externalMethod` runs on the caller's thread with kernel copies (so `nord2_gpu_call_valid`, locks, contexts, budgets are identical to the MIG path); scalars, struct output and the method's IOReturn (`result`) are copied out and `done = 'N2TD'` is set last. The trap returns success once the call ran; a refusal before running leaves `done` unset, which the frontend reads as "no trap" and falls back to `IOConnectCallMethod`.
Costs/benefits: no Mach message, no MIG. The reference measured 1.6 us per trap against 15-25 us per MIG call (A55 at 2 GHz); at ~32 calls per command (c6l) that is ~0.5 ms per command of CPU on the encode/submit thread.
Host tests (`nord2_trap_abi_test.c`, mutants killed: size check, `done` check, scalar-count check, pointer-without-size, scalar clamp, `done` set, struct_out clamp, struct_out bound): layout and constants equal to the frontend's, STATUS is 88 bytes (what the probe expects), the calls the frontend makes (STATUS probe, SUBMIT_JM, WAIT_SEQ with and without fault info, LOG) pass the trap checks AND `nord2_gpu_call_valid`, a wrong shape is still refused by the shared validator, reply packing (clamps, cleared slots, error result with `done`).
Not testable on the host: the IOKit adapter itself (compiled with the real toolchain only). First device check: the frontend's probe turns the trap on when STATUS through the trap returns an 88-byte reply with `done` set; `NORD2_METAL_TRAP=0` forces MIG for an A/B.
